# 手机端拍照检测训练路径

## 沟通背景

用户提出：如果业务需要在手机端直接拍照检测图片，训练路径应该怎么走。

## 结论

手机端直接拍照检测不是重新换一套训练方法，而是在当前 YOLO 检测训练链路上增加两类关键要求：

1. 训练数据必须覆盖手机端真实拍摄场景。
2. 训练完成后必须增加移动端格式导出和真机验证闭环。

推荐先用当前项目的多品牌/单品牌 YOLO 检测链路形成 `best.pt`，再按目标端导出：

- iOS：CoreML。
- Android：LiteRT/TFLite 或 NCNN。
- 如果手机只是拍照上传、由服务端检测：优先 ONNX/TensorRT，不必第一阶段做端侧模型。

## 推荐训练路径

```text
手机端真实拍照样本
→ 原始图片池 raw/images
→ OCR/YOLO-World/YOLOE visual prompt 辅助预标注，或直接人工标注
→ Label Studio 人工复核
→ 正式 YOLO 数据集 images/train|val|test + labels/train|val|test
→ 训练轻量 YOLO 模型
→ 得到 best.pt
→ 导出移动端格式
→ 手机真机拍照测试
→ 回流误检/漏检样本继续训练
```

## 当前项目中的关键路径

正式训练数据路径仍然是：

```text
datasets/<当前品牌或multibrand>/images/train
datasets/<当前品牌或multibrand>/images/val
datasets/<当前品牌或multibrand>/images/test
datasets/<当前品牌或multibrand>/labels/train
datasets/<当前品牌或multibrand>/labels/val
datasets/<当前品牌或multibrand>/labels/test
```

训练输出路径：

```text
models/train/<数据集名>/weights/best.pt
models/<数据集名>-best.pt
```

移动端导出建议输出到后续新增的独立目录，例如：

```text
models/mobile/ios/<数据集名>.mlpackage
models/mobile/android/<数据集名>.tflite 或 <数据集名>_ncnn_model/
```

## 手机端样本采集要求

首版训练集必须覆盖：

- 不同手机型号。
- 竖拍、横拍。
- 近距离、远距离。
- 模糊、低光、反光、过曝。
- 倾斜、遮挡。
- 货架拥挤、商品重叠。
- 不同国家、不同门店类型。

不能只使用历史 Excel 图片训练，否则手机端实拍时容易出现召回率下降。

## 模型选择建议

- PoC / 首版端侧：优先 `yolo26n.pt` 或 `yolo26s.pt`。
- 首版图片尺寸：建议先用 `imgsz=640` 建立速度和召回基线。
- 如果小包装漏检明显：再对比 `imgsz=960` 或 `yolo26m.pt`，但必须做真机延迟验证。

## 执行建议

当前项目可先沿用：

```bash
make workflow-after-ls BRAND=all LS_PROJECT_ID=<项目ID> TRAIN_BASE_MODEL=models/yolo26s.pt TRAIN_EPOCHS=100 TRAIN_IMGSZ=640 TRAIN_DEVICE=mps
```

训练完成后得到：

```text
models/multibrand-best.pt
```

再基于 Ultralytics export 导出移动端格式。后续如果确定要端侧部署，需要补充 `make mobile-export-ios`、`make mobile-export-android`、`make mobile-validate` 等命令。
