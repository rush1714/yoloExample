## 问题 1：Label Studio `varchar(50)` 报错原因

当前 `scripts/label_studio/apply_import.py` 中会按 Makefile 传入的 `LS_PROJECT_TITLE` 创建 Label Studio 项目。

本次标题大约是：

```text
kleesoft_purple, allround_purple GH v2026-09-20
```

长度接近 Label Studio `Project.title` 字段的 50 字符限制。若同名项目已经存在，`next_project_title()` 会追加 ` (2)`、` (3)` 等后缀，导致最终标题超过 50 字符，从而在 `Project.objects.create(...)` 写库时报：

```text
value too long for type character varying(50)
```

### 计划修复

在 `scripts/label_studio/apply_import.py` 中增加标题长度安全处理：

1. 从 `Project._meta.get_field("title").max_length` 获取真实最大长度，默认兜底 50。
2. 修改 `next_project_title()`：
   - 基础标题不重复时，也先截断到最大长度；
   - 需要追加 ` (2)` 等后缀时，先给后缀预留长度，再截断基础标题；
   - 保证每次查询和最终创建的标题都不超过数据库字段限制。
3. 控制台/Makefile 仍可以展示完整业务含义，但写入 Label Studio 的项目标题自动变短，避免失败。

## 计划采用的新统一目录结构

### 统一数据集根目录

后续同一国家、版本、类别组合只生成一套数据集根目录：

```text
datasets/<COUNTRY>/<DATA_VERSION>/<LABEL_DATASET_NAME>/
```

本次示例对应：

```text
datasets/GH/v2026-09-20/general_kleesoft_purple_allround_purple/
```

### 统一子目录

```text
datasets/GH/v2026-09-20/general_kleesoft_purple_allround_purple/
├── raw/
│   ├── images/                         # Excel 下载图片；本地目录导入也建议沉淀/引用到这里
│   └── metadata/
│       └── download_report.csv
├── label_studio/
│   ├── label_studio_import.json        # 本地/Excel 图片 LS 导入 JSON
│   ├── s3_label_studio_import.json     # S3/proxy 图片 LS 导入 JSON，如启用 S3 流程
│   ├── label_config.xml
│   └── exports/
├── ocr/
├── pseudo/
├── images/
│   ├── train/
│   ├── val/
│   └── test/
├── labels/
│   ├── train/
│   ├── val/
│   └── test/
└── s3/
    └── metadata/
        ├── s3_images.json
        ├── s3_images.csv
        ├── s3_download_urls.txt
        ├── ec2_image_manifest.json
        └── ec2_image_manifest.csv
```

说明：

- `raw/`、`label_studio/`、`images/`、`labels/` 是数据集自身的通用标准目录。
- `s3/` 只保存 S3 上传清单、EC2 下载清单等 S3 辅助元数据，不再作为 `datasets/s3/...` 的一级来源目录。
- 是否来自 Excel、本地目录或 S3，只作为“导入方式/图片地址方式”，不再影响数据集根目录命名。
