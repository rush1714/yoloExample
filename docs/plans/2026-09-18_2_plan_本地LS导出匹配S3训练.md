# 本地 LS 导出匹配 S3 训练清单计划

## 背景

用户当前真实流程不是“先上传 S3 再用 S3/Nginx URL 导入 Label Studio”，而是：

```text
本地图片 → 用本地地址导入 Label Studio → 人工标注 → 导出 Label Studio JSON → 再把对应图片上传到 S3 → 希望 EC2 从 S3 下载图片并训练
```

此时 Label Studio 导出中的图片地址仍是本地地址，例如 `/data/local-files/?d=/path/to/image.jpg` 或 `local_path`，不包含 `s3_bucket` / `s3_key` / `s3_uri`。因此现有 `2-brand-s3-workflow-after-ls` 不适用，因为它要求 LS 导出任务本身已经带有 S3 元数据。

## 已阅读上下文

- `scripts/label_studio/export_single_class_to_yolo.py`：可解析本地 LS 导出中的 `local_path` 和 `/data/local-files/?d=...`，并生成本地 YOLO images/labels。
- `scripts/label_studio/export_s3_single_class_to_yolo.py`：可从带 S3 字段的 LS 导出生成 YOLO labels 和 EC2 下载清单，但无法处理只有本地地址的 LS 导出。
- `scripts/s3/upload_images_to_s3.py`：上传本地图片后生成 `s3_images.json/csv`，记录 `local_path`、`relative_path`、`s3_bucket`、`s3_key`、`s3_uri` 等字段。
- `makefiles/brand-s3-ec2/Makefile.mk`：已有 S3 上传、S3 LS 导出转换、EC2 上传/下载/训练命令。
- `web-console/server.js`：S3 菜单和 EC2 菜单均由 `COMMAND_GROUPS` 白名单驱动，需要把新命令加入菜单才能执行。

## 核心设计

新增一条专门适配“本地 LS 标注 + S3 上传清单”的转换链路：

```text
本地 LS 导出 JSON
+
S3 上传清单 s3_images.json
→
YOLO labels/{train,val,test}
+
ec2_image_manifest.json/csv
+
config/generated/s3_<S3_DATASET_NAME>.yaml
```

### 匹配规则

脚本会从本地 LS 导出任务中提取：

- `data.local_path`
- `data.image` 中 `/data/local-files/?d=...` 的真实本地路径
- `data.relative_path`
- `data.image_name`

再与 `s3_images.json` 中记录匹配：

1. 优先按解析后的绝对 `local_path` 匹配。
2. 其次按 `relative_path` 匹配。
3. 最后按 `image_name` 匹配；若文件名重复造成歧义，则跳过并写入 warning。

匹配成功后，用本地 LS annotation 生成 YOLO label，但 EC2 manifest 使用匹配到的 S3 bucket/key/uri。这样 EC2 后续可以从 S3 下载图片，而无需上传本地 images 大文件。

## 拟实施方案

### 1. 新增转换脚本

新增 `scripts/label_studio/export_local_s3_to_yolo.py`：

- 读取本地 LS 导出 JSON。
- 读取 S3 上传清单 `s3_images.json`。
- 复用 `export_single_class_to_yolo.py` 中的：
  - `load_export_tasks`
  - `task_image_path`
  - `select_annotation`
  - `annotation_to_yolo_lines`
  - `split_by_index`
- 复用/对齐 `export_s3_single_class_to_yolo.py` 中的输出结构：
  - 只写 `labels/{train,val,test}`，不复制本地 images。
  - 写 `metadata/ec2_image_manifest.json`。
  - 写 `metadata/ec2_image_manifest.csv`。
  - 写转换报告 JSON/CSV。
  - 写 `config/generated/s3_<dataset>.yaml`。
- 输出 warning：未匹配 S3 记录、重复文件名匹配、无有效 annotation、无目标 label 等。

### 2. 新增 Make 命令

修改 `makefiles/brand-s3-ec2/Makefile.mk`：

- 新增目标：
  - `local-ls-s3-to-yolo`：使用已有 `LOCAL_LS_EXPORT_PATH` + `S3_MANIFEST_JSON` 生成 S3 EC2 训练输入。
  - `2-local-ls-s3-workflow-after-ls`：先执行 `local-dir-ls-export`，再执行 `local-ls-s3-to-yolo`。适合用户还没有导出 LS 时一键导出并转换。
- 关键参数：
  - `LOCAL_LS_EXPORT_PATH`
  - `S3_MANIFEST_JSON`
  - `S3_DATASET_NAME`
  - `S3_LABEL_NAME`
  - `S3_DATASET_ROOT`
  - `S3_DATA_YAML`
  - `S3_EC2_IMAGE_MANIFEST_JSON`
  - `S3_EC2_IMAGE_MANIFEST_CSV`
  - `S3_LS_TO_YOLO_CLEAR`
  - `S3_LS_TO_YOLO_SKIP_EMPTY`

### 3. Web 控制台入口

修改 `web-console/server.js`：

在 “图片来源 / 标注准备 → 本地目录 → S3 → LS” 菜单中增加：

- `本地 LS 导出生成 S3 EC2 清单` → `local-ls-s3-to-yolo`
- `一键导出本地 LS 并生成 S3 EC2 清单` → `2-local-ls-s3-workflow-after-ls`

这样用户当前流程下一步可以直接在控制台执行：

```text
图片来源 / 标注准备 → 本地目录 → S3 → LS → 本地 LS 导出生成 S3 EC2 清单
```

若需要从 LS 项目重新导出，则执行：

```text
图片来源 / 标注准备 → 本地目录 → S3 → LS → 一键导出本地 LS 并生成 S3 EC2 清单
```

然后继续执行已有：

```text
EC2 训练 / 推理 / 下载 → S3 图片数据集 → EC2 → 一键上传并训练 S3 数据
```

### 4. 文档与架构同步

- 更新 `makefiles/brand-s3-ec2/README.md`：新增“本地 LS 标注后转 S3 EC2 训练”的流程说明与命令示例。
- 更新 `设计.md`：在 S3 训练图片管理章节补充该兼容路径。
- 更新本计划文件执行结果。

### 5. 测试与静态检查

- 新增/扩展 `tests/test_brand_s3_ec2_workflow.py`：
  - 本地 LS 导出按 `local_path` 匹配 S3 上传清单，生成 labels 和 `ec2_image_manifest.json/csv`。
  - 文件名重复时不会错误匹配，会写 warning。
  - Makefile 包含 `local-ls-s3-to-yolo` 和 `2-local-ls-s3-workflow-after-ls`。
- 执行：
  - `uv run python -m unittest discover -s tests -p 'test_brand_s3_ec2_workflow.py'`
  - `uv run pylint scripts/label_studio/export_local_s3_to_yolo.py tests/test_brand_s3_ec2_workflow.py`
  - `node --check web-console/server.js`

## 预期结果

用户当前“LS 中是本地地址、图片后来上传 S3”的流程可以生成 EC2 所需的 S3 下载清单。之后无需上传本地 images 到 EC2，可继续使用已有 `3-brand-s3-workflow-ec2-train` 在 EC2 端从 S3 下载图片并训练。
