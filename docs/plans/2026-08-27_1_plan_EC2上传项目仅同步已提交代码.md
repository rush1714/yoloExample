# EC2 上传项目仅同步已提交代码计划

## 背景

用户反馈 `diaper-ec2-upload-project` 会把本地 Git 未提交的修改也上传到 EC2。当前实现使用 `rsync` 直接同步工作区目录，所以会包含未提交文件、未暂存修改等。

## 目标

修改 `diaper-ec2-upload-project` 的实现，让它默认只上传 Git 已提交版本的项目代码，不上传本地未提交修改。

## 方案

1. 修改 `scripts/cloud/ec2_diaper_workflow.py` 的 `upload_project`：
   - 不再直接 `rsync PROJECT_ROOT/`。
   - 改为基于 `git archive HEAD` 生成临时 tar 包。
   - 通过 `ssh` 在 EC2 创建项目目录。
   - 通过 `scp` 上传 tar 包。
   - 通过远程 `tar -xzf` 解压到 `EC2_PROJECT_ROOT`。
   - 删除远程临时 tar 包。
   - 删除本地临时 tar 包。
2. 保持 dry-run 语义：默认只打印将执行的命令；`EC2_EXECUTE=1` 才执行。
3. 为需要调试未提交代码的特殊场景预留参数，例如 `--include-working-tree`；但默认不使用，避免误传未提交内容。
4. 同时修复 EC2 Make 命令中可选参数为空导致末尾 `\` 的问题，至少覆盖 `diaper-ec2-upload-project`。
5. 更新 `makefiles/diaper-category-ec2/README.md`，说明：
   - 默认只上传 `HEAD` 已提交内容。
   - 如果要上传最新修改，必须先 commit。
   - 不建议上传未提交工作区到 EC2。

## 验证

- `make -n 01-diaper-ec2-upload-project EC2_HOST=example` 展开命令不再包含直接 rsync 工作区。
- Python 编译检查通过。
- 相关单元测试/现有测试通过。
- `git diff --check` 通过。

## 不做

- 不实际连接 EC2。
- 不自动提交本地修改。
