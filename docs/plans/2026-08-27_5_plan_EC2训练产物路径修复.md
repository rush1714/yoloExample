# EC2 训练产物路径修复计划

## 现象

实际训练输出为：

```text
Results saved to /home/ec2-user/yoloExample/runs/detect/models/train/diaper_category_CI_v2026-08-27_01-2
```

但当前 EC2 评估与模型导出逻辑假设路径为：

```text
models/train/diaper_category_CI_v2026-08-27_01/
```

因此 `04-diaper-ec2-evaluate` 会读取错误 run 目录，`best.pt` 导出路径也可能与实际训练结果不一致。

## 根因

项目 `scripts/training/train.py` 调用 `model.train(project="models/train", name=...)`，但 Ultralytics 8.4 运行时将结果保存到：

```text
runs/detect/models/train/<name[-N]>/
```

此外，因默认 `exist_ok=False`，同名训练重复执行会自动追加 `-2`、`-3` 等后缀。因此不能通过固定 `models/train/<name>` 推导实际 run 目录。

## 修复方案

1. 修改 `scripts/training/train.py`：
   - 训练完成后从 `model.trainer.save_dir` 获取真实运行目录。
   - 将真实 run 目录中的 `weights/best.pt` 复制到 `--export-model`。
   - 输出真实 run 目录，避免错误提示固定路径。

2. 修改 `scripts/cloud/ec2_diaper_workflow.py`：
   - 远程训练结束后写入一个运行清单文件，例如：

     ```text
     artifacts/diaper_category/<country>/<version>/<profile>/latest-run.txt
     ```

     内容为真实相对 run 目录。
   - `evaluate` 优先读取该清单文件定位实际 run 目录；不存在时才退回旧默认路径。
   - 训练命令的 `--export-model` 改为 `EC2_REMOTE_FINAL_MODEL`，确保持久模型归档在固定路径。

3. 修改 `scripts/reports/summarize_yolo_run.py`：
   - 兼容实际 run 目录并归档产物。
   - summary 中明确记录 `run_dir` 和固定导出模型路径。

4. 修改 Makefile / README：
   - 明确训练可出现 `-2`、`-3` 后缀。
   - `04-diaper-ec2-evaluate` 不再要求用户手工传 run 目录，自动读取 `latest-run.txt`。

## 验证

- 本地用临时目录模拟存在 `runs/detect/models/train/name-2`，验证脚本会选择该真实目录。
- EC2 工具 dry-run 中应包含：训练后写入 `latest-run.txt`，评估时读取该文件。
- 不连接 EC2。
- Python 编译检查、单元测试、`make -n 03...`、`make -n 04...` 和 `git diff --check`。
