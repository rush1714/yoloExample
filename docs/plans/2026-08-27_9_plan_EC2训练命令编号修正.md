# EC2 训练命令编号修正计划

## 问题

用户将 EC2 训练流程按阶段拆分为 smoke、baseline、improve 的训练、评估、下载归档子步骤，但当前 Makefile 存在：

- `.PHONY` 仍保留旧目标名，如 `06-diaper-ec2-train-baseline`，导致执行时显示 `Nothing to be done`。
- 新目标 `04-1`、`04-2` 等未加入 `.PHONY`。
- smoke 下载归档命名为 `03-4`，编号跳过 `03-3`。
- 目标说明仍使用旧的 `06` / `07` 序号。
- baseline/improve 的评估与下载通过 target-specific variable 设置 profile，意图不够直观，易受 Make 解析方式影响。

## 修改方案

1. 将 `.PHONY` 更新为实际存在的编号目标。
2. 使用以下完整执行顺序：

```text
01-diaper-ec2-upload-project              # 非 Git 部署环境才使用
02-diaper-ec2-upload-data                 # 新国家/版本首次上传数据才使用
03-1-diaper-ec2-train-smoke
03-2-diaper-ec2-evaluate-smoke
03-3-diaper-ec2-download-artifacts-smoke
04-1-diaper-ec2-train-baseline
04-2-diaper-ec2-evaluate-baseline
04-3-diaper-ec2-download-artifacts-baseline
05-1-diaper-ec2-train-improve
05-2-diaper-ec2-evaluate-improve
05-3-diaper-ec2-download-artifacts-improve
06-diaper-ec2-predict
07-diaper-ec2-download-model
```

3. 对评估和下载目标使用递归 Make 明确传递训练档位：

```make
$(MAKE) --no-print-directory diaper-ec2-evaluate EC2_TRAIN_PROFILE=baseline
$(MAKE) --no-print-directory diaper-ec2-download-artifacts EC2_TRAIN_PROFILE=baseline
```

4. 更新 `makefiles/diaper-category-ec2/README.md` 的顺序和示例。
5. 验证全部编号目标的 `make -n` 展开，重点确认 baseline 正确传 `EC2_TRAIN_PROFILE=baseline`，以及无目标显示 `Nothing to be done`。

## 不做

- 不连接 EC2。
- 不启动或中断正在运行的训练。
- 不改变 smoke/baseline/improve 的模型、imgsz、epoch 配置。
