# 训练图片 S3 清单转 EC2 清单命令计划

## 背景

当前用户已经完成：

1. 本地图片导入 Label Studio。
2. Label Studio 标注完成。
3. 执行“通用本地 LS 转 YOLO”，已经得到本地训练集：

```text
datasets/<COUNTRY>/<DATA_VERSION>/<LABEL_DATASET_NAME>/images/{train,val,test}/
datasets/<COUNTRY>/<DATA_VERSION>/<LABEL_DATASET_NAME>/labels/{train,val,test}/
```

现在用户希望：

- 不上传 `raw/images` 全量图片，因为里面包含大量未标注图片，上传 S3 浪费时间和费用。
- 只上传刚刚生成的训练图片 `images/{train,val,test}` 到 S3。
- 再基于已生成的 YOLO 训练集和 S3 上传清单生成 EC2 下载训练图片需要的 `ec2_image_manifest.json|csv`。
- 后续复用已有 `3-label-s3-workflow-ec2-train` 完成上传 manifest/labels/YAML、EC2 下载 S3 图片并训练。

## 已确认现状

- `scripts/label_studio/export_labels_to_yolo.py` 目前支持：
  - `local`：LS 本地地址导出 -> YOLO `images/labels`。
  - `s3`：LS S3 地址导出 -> YOLO labels + EC2 manifest。
  - `local-s3`：LS 本地地址导出 + S3 上传清单 -> YOLO labels + EC2 manifest。
- 但当前用户需要的是新模式：
  - 已有 YOLO `images/labels` + S3 上传清单 -> EC2 manifest。
  - 不需要再次读取 LS export。
  - 不需要重写/重切分 `images/labels`。
- `scripts/s3/upload_images_to_s3.py` 支持递归上传任意本地目录，若将 `LABEL_LOCAL_IMAGES_DIR` 指向数据集的 `images/` 目录，则上传清单中的 `relative_path` 会是 `train/xxx.jpg`、`val/xxx.jpg`、`test/xxx.jpg`。

## 计划新增能力

### 1. 新增脚本

新增：

```text
scripts/s3/yolo_dataset_to_ec2_manifest.py
```

职责：

1. 读取 YOLO 数据集根目录：

```text
<LABEL_DATASET_ROOT>/images/{train,val,test}/
<LABEL_DATASET_ROOT>/labels/{train,val,test}/
```

2. 读取 S3 上传清单：

```text
<LABEL_DATASET_ROOT>/s3/metadata/s3_images.json
```

3. 按训练图片相对路径匹配 S3 上传记录：

```text
train/xxx.jpg
val/xxx.jpg
test/xxx.jpg
```

匹配优先级：

- `relative_path`
- `local_path` 归一化路径
- `training_image_name` / `image_name` 作为兜底（若重复则报 warning，不做模糊错配）

4. 读取对应 label 文件，统计：

- `box_count`
- `class_counts`

5. 写出 EC2 训练图片清单：

```text
<LABEL_DATASET_ROOT>/s3/metadata/ec2_image_manifest.json
<LABEL_DATASET_ROOT>/s3/metadata/ec2_image_manifest.csv
```

每条 item 字段保持和现有 `export_labels_to_yolo.py` 生成的 manifest 兼容：

```json
{
  "image": "...",
  "label": "...",
  "split": "train",
  "box_count": 1,
  "class_counts": {"xxx": 1},
  "source_task_id": "",
  "relative_path": "train/xxx.jpg",
  "training_image_name": "xxx.jpg",
  "s3_bucket": "...",
  "s3_key": "...",
  "s3_uri": "...",
  "source_url": "..."
}
```

6. 写转换报告 JSON/CSV，便于排查未匹配图片、缺 label、空 label 等问题。

### 2. 新增 Make 目标

在 `makefiles/label-workflow/Makefile.mk` 新增：

```text
label-yolo-s3-to-ec2-manifest
```

建议命令：

```bash
make label-yolo-s3-to-ec2-manifest \
  COUNTRY=GH \
  DATA_VERSION=v2026-09-20 \
  LABEL_SET=general \
  LABELS=kleesoft_purple,allround_purple
```

默认读取：

```text
LABEL_DATASET_ROOT/images
LABEL_DATASET_ROOT/labels
LABEL_S3_MANIFEST_JSON
```

默认输出：

```text
LABEL_S3_EC2_IMAGE_MANIFEST_JSON
LABEL_S3_EC2_IMAGE_MANIFEST_CSV
LABEL_S3_LS_TO_YOLO_REPORT 或新增 LABEL_YOLO_S3_TO_EC2_REPORT
```

### 4. 推荐用户新流程

新增后用户流程应为：

```text
1. Label Studio → 导出 / 合并 / 转 YOLO → 通用本地 LS 转 YOLO
2. 图片来源 / 标注准备 → 本地目录 → S3 → LS → 上传本地图片到 S3
   - LABEL_LOCAL_IMAGES_DIR 指向 datasets/.../images
   - LABEL_RECURSIVE=1
3. Label Studio → 导出 / 合并 / 转 YOLO → 已生成 YOLO + S3 清单转 EC2 清单
4. EC2 训练 / 推理 / 下载 → S3 图片数据集 → EC2 → 一键上传并训练 S3 数据
```
