# EC2 代码同步规则修正计划

## 更正内容

前一轮说明中把“不需要执行的命令”误写为 `02-diaper-ec2-upload-data`。

正确规则应为：

- **不需要执行 `01-diaper-ec2-upload-project`**：EC2 已通过 `git clone` 管理项目代码，后续代码更新应使用 Git 同步。
- **`02-diaper-ec2-upload-data` 仍保留**：仅当 EC2 上不存在某个新的 `DIAPER_COUNTRY` / `DIAPER_VERSION` 数据集时，用它上传数据集；已有数据集不重复上传。
- 训练 YAML 不需要由 `02` 上传：`03/06/07` 训练命令会在 EC2 训练前自动生成使用绝对数据目录的 YAML。

## 拟修改内容

1. 修正 `makefiles/diaper-category-ec2/README.md`：
   - 明确 `01` 是旧的 rsync 项目代码上传方式。
   - EC2 已 git clone 时，禁止/不建议使用 `01`。
   - 给出 Git 同步步骤：本地提交后，EC2 执行 `git pull`。
   - 恢复 `02` 的准确定位：新国家/新版本数据首次上传时使用。

2. 修正 `makefiles/diaper-category-ec2/Makefile.mk`：
   - 给 `01-diaper-ec2-upload-project` 标注为“仅非 Git 部署环境使用”。
   - 保留 `02-diaper-ec2-upload-data`，标注为“仅首次上传新国家/版本数据”。

3. 修正当前 YAML 路径修复计划和 EC2 流程报告中的文字，消除将 `02` 误标为不需要的表述。

## 不修改内容

- 不删除 `01`，保留给非 Git 部署场景。
- 不删除 `02`，保留给新数据集上传场景。
- 不连接 EC2，也不执行 Git、SSH、rsync 操作。

## 验证

- 搜索 README、Makefile 和计划中 `01` / `02` 的说明，确保规则一致。
- 执行 `make -n 01-diaper-ec2-upload-project` 与 `make -n 02-diaper-ec2-upload-data`，确认目标都仍可展开。
- 执行 `git diff --check`。
