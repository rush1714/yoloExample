# EC2 命令顺序标注与 Label Studio 重复导入排查计划

## 背景

用户反馈：

1. 希望在 `makefiles/diaper-category-ec2/Makefile.mk` 中把 EC2 相关执行命令按顺序标清楚。
2. 使用 `make diaper-workflow-to-ls` 后感觉 Label Studio 被导入了两次，需要验证原因。

## 初步排查结论

通过 `make -n diaper-workflow-to-ls DIAPER_COUNTRY=CI DIAPER_VERSION=v2026-08-26_01` 展开命令观察到：

- 真正生成导入 JSON 的命令只有一次：`scripts/label_studio/generate_single_class_import.py`。
- 真正执行 Label Studio 导入的 `apply_import.py` 只有一次。
- 展开中还会出现：
  - `ls-db-check`：数据库可用性检查，不是导入。
  - `prepare-dirs`：当前会创建通用 `$(LS_EXPORT_DIR)`，默认指向 `datasets/multibrand/...`，这不是导入，但容易让人误以为混入了旧流程。
- `apply_import.py` 当前设计是每执行一次都会新建一个 Label Studio 项目；如果重复运行 `diaper-workflow-to-ls`，会再次导入并创建新项目，这是预期但需要在命令和 README 中明确提醒。

## 拟修改内容

1. **给 EC2 命令标执行顺序**
   - 在 `makefiles/diaper-category-ec2/Makefile.mk` 中调整注释和目标说明，标记：
     - `01 diaper-ec2-upload-project`
     - `02 diaper-ec2-upload-data`
     - `03 diaper-ec2-train-smoke`
     - `04 diaper-ec2-evaluate`
     - `05 diaper-ec2-download-artifacts`
     - `06 diaper-ec2-train-baseline`
     - `07 diaper-ec2-train-improve`
     - `08 diaper-ec2-predict`
     - `09 diaper-ec2-download-model`
   - 同步更新 `makefiles/diaper-category-ec2/README.md` 的推荐执行顺序。

2. **减少 `diaper-workflow-to-ls` 的混淆输出**
   - 新增 `diaper-prepare-dirs`，只创建纸尿裤大类相关目录：
     - `$(TMP_DIR)`
     - `$(LS_WORK_DIR)`
     - `$(LOG_DIR)`
     - `$(DIAPER_LS_EXPORT_DIR)`
   - 将 `diaper-ls-apply` 和 `diaper-ls-export` 的依赖从通用 `prepare-dirs` 改为 `diaper-prepare-dirs`，避免 dry-run 里出现 `datasets/multibrand/label_studio/exports`。

3. **明确重复导入规则**
   - 在 `diaper-ls-apply` 目标注释和 README 中说明：
     - 每执行一次 `diaper-ls-apply` / `diaper-workflow-to-ls` 都会创建一个新的 Label Studio 项目。
     - 如果只是想继续同一个项目标注，不要重复执行导入；直接打开已有项目。
     - 如果确实要重新导入新项目，才重新执行。

4. **验证**
   - 运行：
     - `make -n diaper-workflow-to-ls DIAPER_COUNTRY=CI DIAPER_VERSION=v2026-08-26_01`
     - 确认 `apply_import.py` 只出现一次。
     - 确认不再出现 `datasets/multibrand/label_studio/exports` 的 mkdir。
   - 运行：
     - `make -n diaper-ec2-upload-project ...`
     - `make -n diaper-ec2-upload-data ...`
     - `make -n diaper-ec2-train-smoke ...`
     - `make -n diaper-ec2-evaluate ...`
     - `make -n diaper-ec2-download-artifacts ...`
   - 运行 `git diff --check`。

## 不做的事情

- 不连接 EC2。
- 不实际导入 Label Studio。
- 不删除已有 Label Studio 项目。
