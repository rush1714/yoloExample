# EC2 模型 S3 批量推理验证脚本计划

## 背景

用户希望新增一个使用 EC2 上已训练 YOLO 模型做推理验证的能力：输入可以是 S3 上的 `txt`、Excel、JSON 等图片地址清单，EC2 下载照片并完成推理，推理结果上传到用户指定的 S3 目录，并在本地 Web 控制台中提供新命令入口。

## 已阅读上下文

- `设计.md`：当前架构已有本地推理、EC2 训练、S3 图片数据集到 EC2 训练流程；云端推理建议在“阶段3：YOLO 基础陈列识别”和“S3 训练图片管理与 EC2 下载训练流程”中维护。
- `scripts/inference/predict.py`：当前只支持单张本地图片或 HTTP(S) URL 推理，输出单张 JSON 与带框图。
- `scripts/ec2/s3_workflow.py`：当前负责 S3 训练清单上传、EC2 下载训练图片、训练、评估、下载模型/归档，已有 dry-run/execute 模式和远端脚本上传模式。
- `scripts/ec2/download_s3_manifest_images.py`：当前远端按 `ec2_image_manifest.json` 下载训练图片，支持 public/auto/boto3 下载模式。
- `makefiles/label-workflow/Makefile.mk`、`makefiles/brand-s3-ec2/Makefile.mk`、`makefiles/ec2/Makefile.mk`：已有通用 S3 EC2 训练入口和公共 EC2 连接参数。
- `web-console/server.js`：控制台命令与参数通过 `COMMAND_GROUPS` / `PARAM_DEFINITIONS` 白名单维护。
- `tests/test_brand_s3_ec2_workflow.py`：已有 S3/EC2 纯逻辑测试和控制台/Makefile 白名单断言。

## 实现方案

### 1. 新增 EC2 远端批量推理脚本

新增 `scripts/ec2/s3_batch_predict.py`，职责只放在 EC2 上执行：

1. 接收输入清单路径 `--input`：
   - 支持 `s3://bucket/key`，先下载清单到本地工作目录。
   - 支持 `http(s)://...` 清单 URL。
   - 支持 EC2 本地文件路径。
2. 支持清单格式：
   - `.txt`：每行一个图片地址，忽略空行和 `#` 注释。
   - `.csv`：优先读取指定 `--input-column`，未指定时扫描每个单元格中的图片地址。
   - `.json`：兼容字符串列表、对象列表、`{"items": [...]}`；识别 `s3_uri`、`image_url`、`url`、`source_url`、`https_url`、`public_url`、`s3_bucket + s3_key` 等字段。
   - `.xlsx` / `.xlsm`：使用现有依赖 `openpyxl` 读取；优先 `--input-column`，未指定时扫描所有单元格。
   - `.xls` 先给出明确提示：旧二进制 Excel 暂不作为默认实现，建议另存为 `.xlsx`。
3. 下载图片到 EC2 临时/结果工作目录：
   - `s3://...` 用 `boto3` 下载。
   - `http(s)://...` 用标准库下载。
   - 本地路径直接读取。
   - 支持 `--download-mode auto|public|boto3` 与 `--public-base-url`，沿用当前训练下载语义。
4. 使用 `ultralytics.YOLO` 对下载后的图片逐张推理：
   - 参数支持 `--model`、`--conf`、`--imgsz`、`--device`、`--limit`。
   - 输出每张图片的检测框、类别、置信度、坐标、`class_counts` / `total_count`。
   - 保存带框图和单图 JSON。
5. 输出汇总结果：
   - `summary.json`：总图片数、成功/失败数量、按类别聚合计数、每张图片结果路径与错误。
   - `summary.csv`：便于快速查看每张图的 `total_count`、类别计数和状态。
   - `annotated/`：带框图片。
   - `json/`：单图推理 JSON。
6. 上传结果到用户指定 `--output-s3-uri s3://bucket/prefix`：
   - 使用 `boto3` 递归上传 `summary.json`、`summary.csv`、`annotated/`、`json/`。
   - 输出最终 S3 结果目录和关键文件地址。

### 2. 扩展 EC2 编排脚本

修改 `scripts/ec2/s3_workflow.py`：

1. 新增 action：`predict-s3-manifest`。
2. 新增上传远端推理脚本函数，把 `scripts/ec2/s3_batch_predict.py` 同步到 EC2。
3. 新增远端命令构造：
   - 在 `EC2_PROJECT_ROOT` 下执行。
   - 默认模型使用训练产物 `--remote-final-model`。
   - 支持显式覆盖 `--predict-model`。
   - 默认输出工作目录按数据集和 `EC2_RUN_NAME` 分层，例如 `outputs/ec2_predict/<dataset>/<run_name>/`。
4. 保留既有默认 dry-run 机制；只有 `EC2_EXECUTE=1` 才真正 SSH 到 EC2 执行推理与 S3 上传。

### 3. 新增 Make 目标与参数

修改 `makefiles/ec2/Makefile.mk` 增加公共推理参数：

- `EC2_PREDICT_MANIFEST_SOURCE`：S3/HTTP/EC2 本地清单路径。
- `EC2_PREDICT_OUTPUT_S3_URI`：推理结果上传目标，必填，格式 `s3://bucket/prefix`。
- `EC2_PREDICT_MODEL`：EC2 上模型路径；留空时使用当前流程的训练产物 best.pt。
- `EC2_PREDICT_CONF`：推理置信度，默认 `0.35`。
- `EC2_PREDICT_IMGSZ`：推理尺寸，默认复用 `EC2_TRAIN_IMGSZ`。
- `EC2_PREDICT_LIMIT`：可选，只处理前 N 张用于 smoke test。
- `EC2_PREDICT_INPUT_COLUMN`：Excel/CSV 指定图片地址列名。
- `EC2_PREDICT_WORK_DIR`：EC2 本地推理工作目录。

修改 `makefiles/label-workflow/Makefile.mk`：

- 新增通用命令 `label-s3-ec2-predict-manifest`，用于当前标准 `COUNTRY/DATA_VERSION/LABEL_SET/LABELS` 数据集训练出的模型做 S3 批量推理验证。

修改 `makefiles/brand-s3-ec2/Makefile.mk`：

- 新增兼容命令 `brand-s3-ec2-predict-manifest`，用于旧 `S3_DATASET_NAME` 流程。

## 预期使用示例

```bash
make label-s3-ec2-predict-manifest \
  COUNTRY=GH \
  DATA_VERSION=v2026-09-20 \
  LABEL_SET=general \
  LABELS=kleesoft_purple,allround_purple \
  EC2_HOST=<EC2地址> \
  EC2_KEY=/path/key.pem \
  EC2_RUN_NAME=yolo26m_img960_e100 \
  EC2_PREDICT_MANIFEST_SOURCE=s3://<bucket>/predict-inputs/images.xlsx \
  EC2_PREDICT_INPUT_COLUMN=整改后图片URL \
  EC2_PREDICT_OUTPUT_S3_URI=s3://<bucket>/predict-results/GH/v2026-09-20/run1 \
  EC2_PREDICT_LIMIT=20 \
  EC2_EXECUTE=1
```

默认不传 `EC2_EXECUTE=1` 时仅 dry-run 打印 SSH 命令，便于先检查远端模型、输入清单和输出目录是否正确。
