# 本地 Make 可视化页面计划

## 背景

当前 Makefile 已按模块拆分，但命令数量和参数仍较多，日常执行需要记住目标名和变量名。用户希望增加一个本地可启动的 Node 页面：

- 用分类或 Tab 展示命令，不把全部命令堆在一起。
- 常用参数可以在页面填写。
- 页面可以生成并执行对应 Make 命令。
- 本地目录里的数据做可视化分类统计。
- 图片可以在页面查看。
- 实现不要过度复杂，本地简单启动即可。

## 推荐实现方案

新增一个轻量本地 Web 控制台，不引入前端框架和数据库，尽量只用 Node 内置模块。

### 1. 文件结构

计划新增：

```text
web-console/
├── server.js              # Node HTTP 服务、API、Make 任务执行、数据扫描、图片安全访问
└── public/
    └── index.html         # 单文件页面，内含 CSS 和浏览器端 JS
```

计划新增或更新：

```text
package.json               # 提供 npm start / npm run web-console，本地一条命令启动
README.md                  # 增加本地 Web 控制台使用说明
设计.md                   # 增加“本地流程控制台”说明，保持架构文档同步
Makefile 或 makefiles/common/Makefile.mk # 视实现需要增加 make web-console 便捷目标
```

如果新增 `make web-console`，它只负责启动 Node 服务，不改变原有训练/数据命令行为。

### 2. 页面功能分区

页面使用顶部 Tab 或侧边菜单分类：

1. **总览**
   - 显示项目根目录、品牌数量、主要数据集目录统计。

2. **品牌多类别流程**
   - Excel 导入：`step-1-import-excel` / `excel-import`
   - 常规 OCR：`step-2-ocr`
   - Ollama OCR：`step-2-ocr-llm`
   - YOLO-World 预标注：`step-3-pseudo-label`
   - YOLOE visual prompt：`step-3-pseudo-label-visual`
   - Label Studio 导入：`step-4-import-ls`
   - LS 后训练流程：`workflow-after-ls`

3. **Label Studio**
   - `ls-setup`、`ls-start`、`ls-stop`、`ls-apply`、`ls-export`
   - 提供 `LS_PROJECT_ID`、`LS_PORT`、`BRAND` 等参数输入。

4. **训练与推理**
   - `data-validate`、`train`、`predict`
   - 参数：`BRAND`、`TRAIN_BASE_MODEL`、`TRAIN_EPOCHS`、`TRAIN_IMGSZ`、`TRAIN_BATCH`、`TRAIN_DEVICE`、`TRAIN_RESUME`、`PREDICT_MODEL`、`PREDICT_SOURCE`、`PREDICT_CONF`。

5. **纸尿裤大类 / EC2**
   - `diaper-import-excel`、`diaper-ls-import-json`、`diaper-ls-apply`、`diaper-ls-export`、`diaper-ls-to-yolo`

6. **数据浏览**
   - 按目录分类展示：`datasets/multibrand/raw/images`、`datasets/multibrand/pseudo/images`、`datasets/multibrand/images`、`datasets/diaper_category/.../raw/images`、`outputs/predict`、`models/train`。
   - 展示图片缩略图，点击查看大图。
   - 展示文件名、相对路径、文件大小、修改时间。
   - 可按目录和关键字过滤。

### 3. 命令执行方式

Node 服务提供安全的白名单 API：

- `GET /api/config`：返回可用命令分组、参数模板、品牌列表。
- `GET /api/data/summary`：扫描本地数据目录并返回统计。
- `GET /api/images?root=...&page=...&q=...`：分页读取允许目录下的图片。
- `GET /api/file?path=...`：只允许访问项目内白名单目录的图片文件，防止任意文件读取。
- `POST /api/jobs`：启动 Make 任务。
- `GET /api/jobs/:id`：查看任务状态和日志。
- `POST /api/jobs/:id/stop`：停止仍在运行的任务。

执行 Make 时不用 shell 拼接字符串，而是使用：

```js
spawn('make', [target, 'KEY=value', ...], { cwd: projectRoot })
```

这样可以避免参数被 shell 展开。页面展示完整命令仅作为人工确认/复制用途。

### 4. 参数设计

每个命令卡片只展示常用参数，另外保留“高级参数 JSON / 额外变量”入口。参数名走白名单和格式校验：

- 参数名只允许 `A-Z0-9_`。
- 命令目标只允许内置白名单。
- 路径值不强制限制在项目内，因为现有 Excel 和 SSH key 可能在项目外；但只作为 Make 变量传给子进程，不通过 Web 文件读取。
- 图片浏览接口只允许读取项目内数据/输出目录。

### 5. 数据可视化范围

首版只做轻量可视化：

- 目录统计卡片：图片数、标签数、JSON/CSV 报告数、总大小。
- 数据集拆分统计：`train/val/test` 图片和标签数量。
- OCR / 预标注 / LS 转换报告：如果存在 JSON，则解析关键字段并展示摘要。
- 图片网格和弹窗大图查看。

暂不做复杂图表库、权限系统、数据库、实时 WebSocket。任务日志使用轮询方式读取即可。

### 6. 启动方式

推荐提供两种启动方式：

```bash
npm start
# 或
node web-console/server.js
# 可选
make web-console
```

默认监听：

```text
http://localhost:3000
```

可通过环境变量覆盖端口：

```bash
PORT=3001 npm start
```

## 风险与约束

- 页面会执行本地 Make 命令，因此只面向本机使用，不做公网部署。
- 长时间训练任务可能运行很久，首版使用日志轮询，必要时可以后续升级为 SSE/WebSocket。
- EC2 命令默认 dry-run，避免页面误触发远端执行；需要用户明确把 `EC2_EXECUTE` 改成 `1`。
- 图片和训练数据多为本地大文件，不提交具体数据，只提交控制台代码和文档。

## 2026-09-03 页面交互调整计划

用户反馈当前页面右侧命令卡片展示方式不合适，希望改成 Tabs、Drawer 或 Collapse 中更适合的一种。

### 方案判断

- 不采用 Drawer：当前是本地桌面控制台，命令需要频繁切换和对照参数，抽屉隐藏内容后反而增加点击成本。
- 采用 Tabs + Collapse：顶部 Tabs 负责一级分类（总览、品牌流程、Label Studio、训练推理、纸尿裤/EC2、维护、图片浏览），每个 Tab 内使用折叠面板展示具体命令。这样不会把右侧堆成大量卡片，也能减少页面纵向滚动。
- 保留左侧导航作为窄屏/快捷入口的价值较低，因此计划移除左侧导航，改成顶部横向 Tab，页面主体单列展示。

### 具体改动

1. 修改 `web-console/public/index.html` 的布局：
   - 从「左侧 nav + 右侧内容」改为「顶部 Tabs + 单列内容」。
   - 命令区域从 card grid 改为 accordion/collapse 列表。
   - 每个命令默认折叠，只显示命令名称、说明和一行命令预览。
   - 点击展开后再展示参数表单、复制、执行按钮。

2. 保留现有能力：
   - 数据总览、图片浏览、任务日志不变。
   - 命令执行 API 不变。
   - EC2 dry-run 提醒继续保留。
   - 移动端保持自适应，Tabs 可横向滚动。

3. 更新文档和记录：
   - `README.md` 中把“按 Tab 分类展示命令”描述改成“顶部 Tabs + 折叠命令面板”。
   - 本计划文件追加执行记录。
