# 通用类别配置简化计划

## 背景

用户反馈当前 `config/label_categories.json` 不符合预期：

- 文件里出现了 `brands` 这类历史品牌集合，但用户需要的是一个“都是我可以自己定义的类别”的通用配置。
- 控制台参数 `LABELS` 的下拉/多选里不应该出现 `All` 或 `all` 选项；如果要选择全部类别，直接把所有类别全选即可。
- 当前用户的数据链路是：本地图片导入 Label Studio，Label Studio 中显示的是本地地址；标注导出后，已把对应图片上传到 S3；下一步需要通过本地 LS 导出与 S3 上传清单匹配，生成 EC2 下载训练清单，再在 EC2 下载图片并训练。

- `scripts/common/label_catalog.py`

- `makefiles/common/Makefile.mk`

- `web-console/public/index.html`

## 当前判断

1. 后端类别解析已经支持“空 `LABELS` 表示全量启用类别”，也兼容 `all`。因此控制台删除 `All/all` 选项后，仍可通过全选所有类别表达“全部”。
2. `config/label_categories.json` 当前包含 `brands` 和 `general` 两套集合。用户明确希望它成为一个可自定义类别配置，因此需要把默认配置简化为一个通用类别集合。
3. 历史品牌 OCR / YOLO-World 兼容入口仍依赖 `LABEL_SET=brands` 或历史 `BRAND` 参数；本次不删除历史脚本能力，但控制台默认通用流程应面向一个自定义类别集合。
4. 与用户当前链路对应的下一步命令应是 `label-local-s3-to-yolo` 或一键 `2-label-local-s3-workflow-after-ls`，随后使用 `3-label-s3-workflow-ec2-train` 或拆分的 EC2 上传 manifest、下载图片、训练命令。

## 修改方案

### 1. 简化 `config/label_categories.json`

将默认类别配置改为单一通用集合，例如：

- `sets[0].name = "general"`
- `display_name = "通用陈列类别"`
- `classes` 中仅保留可自定义示例类别，例如 `diaper`、`allround_purple`；不再包含历史 `brands` 集合。

保留 JSON 结构中的 `sets`，原因是现有解析器、控制台类别管理和 Make 参数都基于这套结构，改成纯数组会扩大改动面；但对用户体验来说，配置文件里只会看到一个通用类别集合，里面都是可自行增删改的类别。

### 2. 调整默认 Make 参数

把通用工作流默认值从历史品牌集合切到通用集合：

- `makefiles/label-workflow/Makefile.mk`：`LABEL_SET ?= general`
- `scripts/config/label_profile.py`：命令行参数 `--label-set` 默认从 `brands` 改为 `general`
- 必要时更新帮助文字，避免继续暗示默认是 `brands/general` 中的 `brands`。

### 3. 控制台 `LABELS` 不再出现 All/all

修改 `web-console/server.js`：

- `labelCatalogOptions()` 的 `labelsBySet` 不再主动在类别列表前插入 `all`。
- 控制台多选框只显示实际类别。
- 保持后端对空 `LABELS`/历史 `all` 的兼容，避免老命令或手工命令失效。

### 4. 控制台默认 `LABEL_SET` 指向通用集合

检查 `web-console/server.js` 参数定义：

- `LABEL_SET` 默认值改为 `general`。
- `LABELS` 默认值改为空字符串或不预选；用户要全量时在页面里全选类别。
- 如果前端已有缓存里的 `LABELS=all`，不主动破坏缓存文件，但新配置选项不再提供 `all`。

### 5. 文档同步

因为类别配置与 S3/EC2 数据流程属于架构约定，本次同步更新：

- `设计.md`：把“空值或 all 表示全部”改为“控制台全选表示全部；命令行空值仍兼容全量，历史 all 仅作为兼容输入”。
- `设计.md`：补充说明默认类别集合为 `general`，`brands` 仅是旧品牌兼容入口或由旧 `brand_keywords.json` 兼容读取，不再作为默认 `label_categories.json` 内容。
- 当前计划文件：实施后追加修改结果和验证结果。

### 6. 验证

计划执行后运行：

- `uv run pylint scripts/common/label_catalog.py scripts/config/label_profile.py`
- `node --check web-console/server.js`
- 如可用，运行相关测试：
  - `uv run pytest tests/test_label_catalog_workflow.py`
  - 必要时补充/调整测试，覆盖 `LABELS` 不含 `all` 的控制台配置输出。

## 用户当前链路的下一步菜单/命令提示

实现完成后，建议在最终回复中明确告诉用户：

1. 如果 Label Studio 项目里是本地图片地址，且图片后来已上传到 S3：
   - 控制台菜单：`Label Studio → 导出 / 合并 / 转 YOLO → 本地 LS + S3 清单转 EC2 清单`
   - Make 命令：
     ```bash
     make label-local-s3-to-yolo \
       COUNTRY=GH \
       DATA_VERSION=v2026-09-18 \
       LABEL_SET=general \
       LABELS=<全选后的类别逗号列表> \
       LABEL_DATASET_NAME=<数据集名> \
       LABEL_LS_EXPORT_PATH=<LS导出JSON路径> \
       LABEL_S3_MANIFEST_JSON=<S3上传生成的s3_images.json> \
       LABEL_LOCAL_IMAGES_DIR=<原始本地图片目录> \
       LABEL_LS_TO_YOLO_CLEAR=1
     ```
2. 然后进入：`EC2 训练 / 评估 / 下载 → S3 图片数据集 → EC2`。
3. 先 dry-run 检查，再加 `EC2_EXECUTE=1` 真执行：
   ```bash
   make 3-label-s3-workflow-ec2-train \
     COUNTRY=GH \
     DATA_VERSION=v2026-09-18 \
     LABEL_SET=general \
     LABELS=<同上类别列表> \
     LABEL_DATASET_NAME=<数据集名> \
     EC2_BASE_MODEL=yolo26m.pt \
     EC2_TRAIN_EPOCHS=100 \
     EC2_TRAIN_IMGSZ=960 \
     EC2_RUN_NAME=yolo26m_img960_e100
   ```
   确认 dry-run 输出无误后再追加：
   ```bash
   EC2_EXECUTE=1
   ```

## 风险与兼容

- 删除默认 `brands` 集合会影响直接使用 `LABEL_SET=brands` 的新通用命令；历史品牌专用命令已改为默认读取 `config/brand_keywords.json`，避免因通用类别配置不再内置 `brands` 而失败。若后续仍需品牌类别，可在控制台里自己新建类别集合或继续使用旧品牌配置。
- 后端仍保留 `all` 兼容，避免已有脚本、旧命令和缓存参数立即失败；本次只是不再在控制台选项中展示 `All/all`。

## 实施结果

- `config/label_categories.json` 已简化为单一 `general` 通用陈列类别集合，默认包含 `diaper` 与 `allround_purple` 两个可自定义示例类别，不再内置 `brands` 集合。
- 通用 Make 工作流默认改为 `LABEL_SET=general`、`LABELS` 空值；命令行空值表示全量类别，历史 `all` 只保留为兼容输入。
- 控制台 `LABEL_SET` 默认改为 `general`，`LABELS` 多选框只展示真实类别，不再展示 `all` 伪选项；没有有效缓存或旧缓存为 `all` 时，页面会默认全选真实类别。
- 历史品牌 OCR/预标注命令默认品牌库改为 `config/brand_keywords.json`，保持 `BRAND=all` 兼容入口可用。
- `scripts/common/label_catalog.py` 已补充“显式全选所有真实类别等价于全量选择”的判断，避免控制台全选后被误判为部分类别并压缩 class_id。
- 已同步更新 `设计.md`、`README.md`、`makefiles/label-workflow/README.md` 中关于通用类别、`LABELS` 全选和历史品牌兼容的说明。
