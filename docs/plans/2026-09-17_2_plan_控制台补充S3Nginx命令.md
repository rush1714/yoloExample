# 控制台补充 S3 Nginx 命令计划

## 背景

用户要求把刚刚新增的命令加到对应控制台的菜单下。结合当前未提交改动与 `docs/plans/2026-09-17_1_plan_S3图片代理改为Nginx.md`，刚刚新增的命令主要是 S3 图片代理切换为 Nginx 后增加的 Make 目标。

## 已阅读上下文

- `设计.md`：本地 Web 控制台通过左侧菜单组织 Make 白名单命令；S3 训练图片流程已说明 Web 控制台应提供上传、代理、导入、标注后转换、EC2 下载/训练/评估/下载。
- `docs/plans/2026-09-17_1_plan_S3图片代理改为Nginx.md`：新增目标包括 `brand-s3-nginx-render-config`、`brand-s3-nginx-start`、`brand-s3-nginx-reload`、`brand-s3-nginx-stop`、`brand-s3-python-proxy-start`。
- `makefiles/brand-s3-ec2/Makefile.mk`：确认这些 Make 目标已存在。
- `web-console/server.js`：当前 S3 菜单已有 `brand-s3-proxy-start`、`brand-s3-nginx-reload`、`brand-s3-nginx-stop`，但缺少直接渲染配置、直接启动 Nginx、直接启动旧 Python 代理三个入口。

## 执行计划

1. 修改 `web-console/server.js` 的 “图片来源 / 标注准备 → 本地目录 → S3 → LS” 分组：
   - 在 `brand-s3-proxy-start` 之后增加 `brand-s3-nginx-render-config`，用于只生成 Nginx 配置与 map，不启动服务。
   - 增加 `brand-s3-nginx-start`，用于直接启动本地 Nginx 图片代理。
   - 保留已有 `brand-s3-nginx-reload` 与 `brand-s3-nginx-stop`。
   - 增加 `brand-s3-python-proxy-start`，用于在 Nginx 不可用时直接启动旧 Python 代理。
2. 补充必要参数定义：
   - `S3_NGINX_BIN`
   - `S3_NGINX_CONF`
   - `S3_NGINX_MAP`
   - `S3_NGINX_CACHE_DIR`
   - `S3_NGINX_PID`
   这些参数用于页面输入、命令预览和后端白名单校验。
3. 检查控制台白名单：
   - `TARGETS` 由 `COMMAND_GROUPS` 自动收集，新增菜单项会自动允许执行。
   - `ALLOWED_VARIABLES` 由 `PARAM_DEFINITIONS` 自动收集，新增参数定义会自动允许传参。
4. 验证：
   - 使用 Node 语法检查验证 `web-console/server.js` 无语法错误。
   - 使用 PyCharm lint 检查修改文件。

## 预期结果

Web 控制台左侧 “本地目录 → S3 → LS” 菜单中可以直接看到并执行完整 S3 Nginx 代理相关命令：生成配置、启动、刷新、停止，以及旧 Python 代理回退入口。
