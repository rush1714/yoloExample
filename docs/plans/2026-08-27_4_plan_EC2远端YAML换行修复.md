# EC2 远端 YAML 换行修复计划

## 现象

修复绝对路径后，EC2 训练仍在读取 YAML 时失败：

```text
yaml.scanner.ScannerError: mapping values are not allowed here
line 1, column 83
```

远程命令中生成 YAML 的片段是：

```bash
printf '%s\n' 'path: ...\ntrain: images/train\nval: images/val...'
```

## 根因

Python 代码构造的是字符串字面量 `"\\n"`，不是实际换行符。通过 `printf '%s'` 写入后，YAML 文件成为单行并包含字符 `\n`，例如：

```text
path: /.../v2026-08-27_01\ntrain: images/train\nval: images/val
```

YAML 解析器将同一行的 `train:` 视为非法映射，因此报错。

## 修复方案

1. 修改 `scripts/cloud/ec2_diaper_workflow.py` 的 `prepare_remote_dataset_yaml`：
   - 使用真实换行符 `"\n".join(...)` 构建 YAML 内容。
   - 使用 shell 的 here-document（`cat <<'EOF'`）写入远端 YAML，避免 `printf` 的转义行为差异。
   - 保持路径为 EC2 绝对路径。

2. 更新本计划记录实际错误与修复结果。

3. 验证：
   - EC2 工具 dry-run 输出中 YAML 内容应显示为多行 here-document。
   - 运行本地 Python 编译检查。
   - 不连接 EC2。

## 用户后续操作

代码提交并在 EC2 执行 `git pull` 后，重新运行：

```bash
make 03-diaper-ec2-train-smoke \
  DIAPER_COUNTRY=CI \
  DIAPER_VERSION=v2026-08-27_01 \
  EC2_EXECUTE=1
```
