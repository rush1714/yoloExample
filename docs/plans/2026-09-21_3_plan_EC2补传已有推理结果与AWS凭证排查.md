## 实现方案

### 1. 远端脚本支持“只上传已有推理结果”模式

修改 `scripts/ec2/s3_batch_predict.py`：

1. 新增 CLI 参数：
   - `--upload-existing-only`：只上传 `--work-dir` 下已有结果，不读取清单、不下载图片、不推理。
2. 在该模式下：
   - `--input` 和 `--model` 不再必填。
   - 校验 `--work-dir` 存在。
   - 调用现有 `upload_results_to_s3(paths, output_s3_uri)`。
   - 上传范围保持为：`summary.json`、`summary.csv`、`source_image_uris.txt`、`json/`、`annotated/`、生成并上传 `uploaded_s3_uris.txt`。
3. 输出 JSON 摘要：
   - `mode=upload-existing-only`
   - `work_dir`
   - `output_s3_uri`
   - `uploaded_files`

这样本次已经生成的 EC2 本地结果目录可以直接复用，不需要重新跑 379 张推理。

### 6. AWS 凭证报错解释与排查建议

用户在 EC2 上执行 `aws configure` 后仍 `NoCredentials`，常见原因：

1. **配置在了错误的 Linux 用户下**：脚本通过 `EC2_USER=ec2-user` SSH 执行，凭证必须在 `/home/ec2-user/.aws/credentials`，如果在 `root`、`ssm-user` 或其他用户下配置，`ec2-user` 读不到。
2. **使用了 profile 但没有设置默认 profile**：如果写在 `[profile xxx]` 或 `[xxx]`，但执行 `aws sts get-caller-identity` 没加 `--profile xxx`，默认链路仍找不到。
3. **AWS CLI v2 新的提示 `aws login` 可能表示当前环境期待 SSO/Identity Center 登录**，如果用的是 SSO 配置，需要执行 `aws sso login --profile <profile>`，但 EC2 批处理不推荐依赖交互式 SSO。
4. **环境变量覆盖/清空**：`AWS_PROFILE` 指向不存在的 profile，或 `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` 为空值覆盖了文件配置。
5. **没有绑定 IAM Role**：如果没有 `~/.aws/credentials`，也没有 EC2 Instance Profile，则 boto3 和 AWS CLI 都会报无凭证。

推荐排查命令：

```bash
whoami
pwd
ls -la ~/.aws
sed -n '1,120p' ~/.aws/credentials
sed -n '1,120p' ~/.aws/config
env | grep '^AWS_' || true
aws configure list
aws sts get-caller-identity
```

如果使用指定 profile：

```bash
aws sts get-caller-identity --profile <profile>
AWS_PROFILE=<profile> aws sts get-caller-identity
```

推荐最终方案仍是给 EC2 绑定 IAM Role/Instance Profile，而不是在 EC2 上保存长期 Access Key。
