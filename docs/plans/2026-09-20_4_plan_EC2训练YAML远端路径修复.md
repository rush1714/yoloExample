# EC2 训练 YAML 远端路径修复计划

## 背景

用户执行：

```bash
make label-yolo-s3-to-ec2-manifest COUNTRY=GH DATA_VERSION=v2026-09-20 LABEL_SET=general LABELS=kleesoft_purple,allround_purple LABEL_LS_TO_YOLO_SKIP_EMPTY=1
make 3-label-s3-workflow-ec2-train COUNTRY=GH DATA_VERSION=v2026-09-20 LABEL_SET=general LABELS=kleesoft_purple,allround_purple ... EC2_EXECUTE=1
```

EC2 训练阶段报错：

```text
训练取消，数据集校验失败：
- train 图片目录不存在：/Users/guobiao/PRO/me/yoloExample/datasets/GH/v2026-09-20/general_kleesoft_purple_allround_purple/images/train
- val 图片目录不存在：/Users/guobiao/PRO/me/yoloExample/datasets/GH/v2026-09-20/general_kleesoft_purple_allround_purple/images/val
- test 图片目录不存在：/Users/guobiao/PRO/me/yoloExample/datasets/GH/v2026-09-20/general_kleesoft_purple_allround_purple/images/test
```

关键现象：错误路径是本机 Mac 路径 `/Users/guobiao/PRO/...`，但训练命令是在 EC2 上执行的。

## 根因判断

`label-s3-ec2-upload-manifest` 当前会把本地 YAML 原样上传到 EC2：

```text
config/generated/GH_v2026-09-20_general_kleesoft_purple_allround_purple.yaml
```

该 YAML 是本地生成的，内容里的 `path:` 指向本机 Mac 数据集绝对路径：

```text
path: /Users/guobiao/PRO/me/yoloExample/datasets/GH/v2026-09-20/general_kleesoft_purple_allround_purple
```

EC2 训练时读取这个 YAML，自然去 EC2 文件系统里找 `/Users/guobiao/.../images/train`，因此报目录不存在。

这和用户已经执行 `label-yolo-s3-to-ec2-manifest` 不冲突：该命令生成了 EC2 图片下载清单，但没有改写训练 YAML 的 `path:` 为 EC2 路径。

## 修复目标

S3/EC2 流程上传到 EC2 的训练 YAML 必须保留本地 YAML 的多类别 `names`，但把 `path:` 改成 EC2 上真实数据集目录：

```text
/home/ec2-user/yoloExample/datasets/GH/v2026-09-20/general_kleesoft_purple_allround_purple
```

这样远端训练脚本校验的是：

```text
/home/ec2-user/yoloExample/datasets/GH/v2026-09-20/general_kleesoft_purple_allround_purple/images/train
/home/ec2-user/yoloExample/datasets/GH/v2026-09-20/general_kleesoft_purple_allround_purple/images/val
/home/ec2-user/yoloExample/datasets/GH/v2026-09-20/general_kleesoft_purple_allround_purple/images/test
```

这些目录应由 `download_s3_manifest_images.py` 根据 `ec2_image_manifest.json` 下载生成。

## 实施计划

### 1. 修改 `scripts/ec2/s3_workflow.py`

新增函数：

```text
remote_data_yaml_text(args) -> str
```

逻辑：

1. 读取本地 `args.data_yaml`。
2. 用 YAML 解析，保留 `train`、`val`、`test`、`names` 等配置。
3. 将 `path` 改成 `remote_project_path(args, remote_dataset_root(args))`。
4. 输出临时 YAML 文件。
5. `upload_manifest()` 上传这个临时 YAML 到 `args.remote_data_yaml`，而不是原样上传本地 YAML。

注意：

- 不能用 `prepare_remote_dataset_yaml()`，因为它是旧单类别兜底逻辑，只会写 `names: 0: <label_name>`，会破坏多类别配置。
- `train()` 仍保留 `--skip-generate-yaml`，但现在远端已有路径正确的多类别 YAML。

### 2. 改善错误提示

`validate_upload_inputs()` 中现在提示用户执行旧命令：

```text
make 2-brand-s3-workflow-after-ls
```

这次顺便改成更贴合当前通用流程：

```text
make label-yolo-s3-to-ec2-manifest
```

并保留对 S3 LS 流程的兼容提示。

### 3. 增加/调整测试

在 `tests/test_brand_s3_ec2_workflow.py` 增加测试：

- 构造一个本地 YAML：`path: /Users/.../datasets/...`，`names` 多类别。
- 调用新函数生成远端 YAML 文本。
- 断言：
  - `path` 已改成 EC2 远端绝对路径。
  - `names` 多类别保持不变。
  - `train/val/test` 仍为 `images/train|val|test`。

### 4. 验证

执行：
