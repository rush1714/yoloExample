# EC2 数据集 YAML 路径修复计划

## 现象

执行：

```bash
make 03-diaper-ec2-train-smoke EC2_EXECUTE=1
```

EC2 已成功：

- 通过 `/opt/pytorch/bin/activate` 激活 PyTorch 环境。
- 识别到 `CUDA:0 (NVIDIA A10G)`。
- 下载 `yolo11n.pt`。

但训练在读取数据集 YAML 时失败：

```text
missing path '/home/ec2-user/datasets/diaper_category/CI/v2026-08-27_01/images/val'
```

实际数据应位于：

```text
/home/ec2-user/yoloExample/datasets/diaper_category/CI/v2026-08-27_01/
```

## 根因

当前 YAML 使用：

```yaml
path: ../../datasets/diaper_category/CI/v2026-08-27_01
```

YAML 放在：

```text
/home/ec2-user/yoloExample/config/generated/
```

Ultralytics 将该相对路径解析到 `/home/ec2-user/datasets/...`，少了一层 `yoloExample`。本地相对路径写法和 EC2 部署目录不一致。

## 修复方案

1. 将单类别纸尿裤 YAML 的 `path` 改成项目根目录内稳定相对路径：

```yaml
path: datasets/diaper_category/<国家>/<版本>
```

这会由 Ultralytics 从当前项目根目录正确解析为：

```text
/home/ec2-user/yoloExample/datasets/diaper_category/<国家>/<版本>
```

2. 修改 `makefiles/diaper-category-ec2/Makefile.mk` 的 `diaper-yaml`，生成上述路径。

3. 同步更新 README/设计文档中的 YAML 示例和说明。

4. 训练前由 EC2 远程命令自动生成当前国家/版本专用 YAML，并使用绝对数据目录：

```yaml
path: /home/ec2-user/yoloExample/datasets/diaper_category/CI/v2026-08-27_01
```

这样不依赖本地 YAML 相对路径，也不要求再次执行 `02-diaper-ec2-upload-data` 上传 YAML；但 `02` 仍保留给首次上传新的国家/版本数据集。

5. 用户已通过 Git clone 管理 EC2 项目代码，因此不使用 `01-diaper-ec2-upload-project`，只需在 EC2 项目目录拉取包含本次修复的代码：

```bash
cd /home/ec2-user/yoloExample
git pull
```

然后重新跑 smoke：

```bash
make 03-diaper-ec2-train-smoke DIAPER_COUNTRY=CI DIAPER_VERSION=v2026-08-27_01 EC2_EXECUTE=1
```

## 验证

- `make -n diaper-yaml ...` 展开路径为 `datasets/diaper_category/...`。
- 新生成 YAML 的 `path` 正确。
- `make -n 02-diaper-ec2-upload-data ...` 和 `make -n 03-diaper-ec2-train-smoke ...` 正确。
- 不连接 EC2，不重复执行用户的远程训练。
