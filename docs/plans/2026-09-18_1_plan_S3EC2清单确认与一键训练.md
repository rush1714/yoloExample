# S3 EC2 清单确认与一键训练计划

## 背景

用户要求：

1. 确认传入 EC2 的 S3 流程里是否使用 `ec2_image_manifest.json` / `ec2_image_manifest.csv`，并检查 EC2 上传 S3、EC2 下载 S3 以及其他相关代码。
2. 新增一个一键流程：上传 S3 数据到 EC2、EC2 从 S3 下载训练图片、EC2 训练 S3 数据，并在 Web 控制台增加入口、代码和说明。

- `设计.md`：S3 训练图片管理章节说明当前 S3 → Label Studio → EC2 训练流程。
- `makefiles/brand-s3-ec2/Makefile.mk`：S3 上传、Label Studio 导入/导出、EC2 上传 manifest、EC2 下载图片、EC2 训练/评估/下载入口。

## 当前确认结论

目前代码里实际存在两类清单，作用不同：

1. `s3_images.json` / `s3_images.csv`
   - 由 `scripts/s3/upload_images_to_s3.py` 生成。
   - 对应 Make 变量：`S3_MANIFEST_JSON ?= $(S3_DATASET_ROOT)/metadata/s3_images.json`。
   - 用途：记录本地图片上传到 S3 后的完整图片地址、S3 bucket/key、https/proxy/nginx URL 等。
   - 主要供 Label Studio 导入 JSON 生成、Nginx 代理配置生成、断点续传使用。

2. `ec2_image_manifest.json` / `ec2_image_manifest.csv`
   - 由 `scripts/label_studio/export_s3_single_class_to_yolo.py` 在标注导出转 YOLO 时生成。
   - 对应 Make 变量：`S3_EC2_IMAGE_MANIFEST_JSON ?= $(S3_DATASET_ROOT)/metadata/ec2_image_manifest.json`、`S3_EC2_IMAGE_MANIFEST_CSV ?= $(S3_DATASET_ROOT)/metadata/ec2_image_manifest.csv`。
   - 用途：只包含“进入训练集”的图片，并额外带有 `split`、`training_image_name`、`label_path`、`box_count` 等训练所需字段。
   - `scripts/ec2/s3_workflow.py` 的 `upload-manifest` 会把这个 JSON 上传到 EC2；`download-images` 和 `train` 会读取这个 JSON，在 EC2 端把 S3 图片下载到 `images/{train,val,test}/`。

因此当前不是简单把传入 EC2 的清单改成 `s3_images.json`。`s3_images.json` 是上传/导入清单；`ec2_image_manifest.json` 是标注完成后的训练下载清单。两者命名虽然相近，但职责不同。后续会在文档和控制台说明中进一步讲清楚，避免误解。

## 拟实施方案

### 1. 加强 EC2 S3 清单检查与报错说明

修改 `scripts/ec2/s3_workflow.py`：

- 在 `upload_manifest` 前增加本地输入检查：
  - `labels/` 目录是否存在；
  - `S3_EC2_IMAGE_MANIFEST_JSON` 是否存在；
  - `S3_DATA_YAML` 是否存在。
- 当 `ec2_image_manifest.json` 不存在但同目录有 `s3_images.json` 时，报错说明：
  - `s3_images.json` 是上传/Label Studio 导入清单；
  - EC2 训练需要先执行 `make 2-brand-s3-workflow-after-ls ...` 生成带 split 和 labels 的 `ec2_image_manifest.json`。
- 在 EC2 端下载命令里加入 manifest 字段校验：缺少 `split`、`s3_bucket`、`s3_key` 时直接给出明确错误，避免远端训练时才失败。

### 2. 新增一键 EC2 S3 训练流程 Make 目标

修改 `makefiles/brand-s3-ec2/Makefile.mk`：

- 新增 `.PHONY` 目标：`3-brand-s3-workflow-ec2-train`。
- 目标依赖/执行顺序：
  1. `brand-s3-ec2-upload-manifest`：上传 labels、EC2 图片下载 manifest、YAML 到 EC2。
  2. `brand-s3-ec2-download-images`：EC2 按 manifest 从 S3 下载训练图片。
  3. `brand-s3-ec2-train`：EC2 训练 S3 数据。
- 保持 EC2 命令默认 dry-run；只有 `EC2_EXECUTE=1` 时真正 SSH/rsync 到远端执行。
- 说明：现有 `brand-s3-ec2-train` 内部也会执行一次下载检查；新增一键目标中单独保留 `brand-s3-ec2-download-images` 是为了让“上传 → 下载 → 训练”的日志和步骤更清晰，重复下载会因目标文件已存在而跳过。

### 3. Web 控制台增加一键入口与参数

修改 `web-console/server.js`：

- 在 “EC2 训练 / 推理 / 下载 → S3 图片数据集 → EC2” 菜单中增加：
  - `一键上传并训练 S3 数据` → `3-brand-s3-workflow-ec2-train`
- 参数包含：
  - `S3_DATASET_NAME`、`S3_LABEL_NAME`、`S3_DATASET_ROOT`
  - `EC2_HOST`、`EC2_USER`、`EC2_KEY`、`EC2_PORT`、`EC2_PROJECT_ROOT`
  - `EC2_BASE_MODEL`、`EC2_TRAIN_EPOCHS`、`EC2_TRAIN_IMGSZ`、`EC2_TRAIN_BATCH`、`EC2_TRAIN_DEVICE`
  - `EC2_RUN_NAME`、`EC2_EXECUTE`
- 补充/确认控制台必要参数定义：`EC2_PORT`、`EC2_PROJECT_ROOT`、`S3_EC2_IMAGE_MANIFEST_JSON`、`S3_EC2_REMOTE_MANIFEST_JSON` 等是否需要展示；如果只依赖 Make 默认值，则不强制展示过多低频路径参数。

### 4. 更新说明文档与架构文档

- 更新 `makefiles/brand-s3-ec2/README.md`：
  - 明确 `s3_images.json` 和 `ec2_image_manifest.json` 的区别。
  - 增加 `3-brand-s3-workflow-ec2-train` 使用示例。
  - 更新命令索引。
- 更新 `设计.md` 的 S3 训练图片管理章节：
  - 增加一键 EC2 训练入口说明。
  - 明确 EC2 下载/训练读取的是 `ec2_image_manifest.json`，不是原始上传清单 `s3_images.json`。
- 更新本计划文件的执行结果。

### 5. 测试与静态检查

- 更新/新增 `tests/test_brand_s3_ec2_workflow.py` 覆盖：
  - EC2 下载命令仍引用 `ec2_image_manifest.json`。
  - `upload_manifest` 在缺失 EC2 manifest 时给出包含 `s3_images.json` / `2-brand-s3-workflow-after-ls` 的提示。
  - 一键 Make 目标存在于 `Makefile.mk`。
- 执行：
  - `uv run python -m unittest discover -s tests -p 'test_brand_s3_ec2_workflow.py'`
  - `uv run pylint scripts/ec2/s3_workflow.py tests/test_brand_s3_ec2_workflow.py`
  - `node --check web-console/server.js`

## 预期结果

- 用户可以明确知道：上传阶段生成 `s3_images.json/csv`；EC2 训练阶段使用标注转换后的 `ec2_image_manifest.json/csv`。
