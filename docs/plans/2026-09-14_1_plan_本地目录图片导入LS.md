# 本地目录图片导入 Label Studio 计划

## 背景

用户需要把本机某个图片目录直接导入到 Label Studio，完成人工标注后再导出为 YOLO 训练集，并希望：

- 增加对应 Make 命令。
- 在本地 Web 控制台中可以填写参数并执行。
- 完成测试验证。
- 写好文档。

## 已阅读上下文

- `scripts/label_studio/generate_single_class_import.py`：当前纸尿裤大类导入依赖下载报告 CSV，不适合直接扫描任意本地目录。
- `scripts/label_studio/export_single_class_to_yolo.py`：已经支持单类别 Label Studio 导出转 YOLO，只要任务 data 中有 `local_path` 或 `/data/local-files/?d=` 图片路径即可复用。
- `scripts/label_studio/apply_import.py`：导入 Label Studio 时支持通过环境变量 `LS_IMPORT_JSON`、`LS_LOCAL_FILES_PATH`、`LS_PROJECT_TITLE`、`LS_LABEL_CONFIG_XML` 指定导入 JSON、本地文件目录、项目标题和标签配置，可复用。
- `makefiles/common/Makefile.mk`：公共 Label Studio 启停、导出、训练、Web 控制台入口在这里。
- `web-console/server.js`：Web 控制台命令白名单和参数定义需要同步新增。

## 实施方案

新增通用“本地目录单类别标注流程”，不绑定纸尿裤，也不依赖 Excel 下载报告。

### 新增脚本

新增 `scripts/label_studio/generate_local_dir_import.py`：

- 扫描用户指定的本地图片目录。
- 支持递归或仅当前层。
- 支持 `.jpg/.jpeg/.png/.webp/.bmp/.tif/.tiff`。
- 生成 Label Studio 导入 JSON。
- 生成单类别矩形框 Label Studio XML 配置。
- 每个任务写入 `/data/local-files/?d=<absolute_path>`、`local_path`、`image_name`、`relative_path`、`meta.source=local-dir`、`meta.dataset_name=<LOCAL_DATASET_NAME>`。
- 支持 `--limit` 小批量试跑。

### 新增 Make 命令

放到 `makefiles/common/Makefile.mk`：

- `local-dir-ls-import-json`

- `1-local-dir-workflow-to-ls`

## 2026-09-14 本地目录到 EC2 训练目录重设计计划

### 背景问题

当前本地目录流程虽然已拆出 `LOCAL_DATASET_ROOT`，但仍然没有和既有 EC2 上传/训练链路形成一套清晰的目录契约。现有 EC2 工具 `scripts/cloud/ec2_diaper_workflow.py` 默认假设远端数据放在：

```text
datasets/diaper_category/<country>/<version>/
```

而本地目录流程默认放在：

```text
datasets/local/<LOCAL_DATASET_NAME>/
```

这会导致后续接 EC2 上传/训练时还要手动映射路径，容易混淆。

### 目标

重新设计本地目录导入/导出结构，使它满足两个场景：

1. **默认简单用法**：本地图片目录导入后输出到项目内稳定目录。
2. **EC2 衔接用法**：同一套输出可以直接通过新的本地目录 EC2 上传/训练命令上传并训练，不再复用纸尿裤专属变量名。

### 新目录约定

本地目录流程统一默认输出为：

```text
datasets/local/<LOCAL_DATASET_NAME>/
├── source/images/                       # 可选：未来如需复制源图，可放这里；当前仍使用 LOCAL_IMAGES_DIR 原路径导入 LS
├── label_studio/
│   ├── local_dir_label_studio_import.json
│   ├── label_config.xml
│   └── exports/
│       ├── label_studio_export.json
│       └── label_studio_to_yolo_report.json
├── images/{train,val,test}/             # 标注后转换出的 YOLO 图片
└── labels/{train,val,test}/             # 标注后转换出的 YOLO 标签
```

允许用户显式覆盖：

```makefile
LOCAL_DATASET_ROOT=/自定义/导出目录
```

但 `LOCAL_DATASET_NAME` 必须是短名称，用于训练 run 名称、YAML 名、远端路径名和模型名。

### EC2 衔接设计

新增本地目录专属 EC2 变量：

```makefile
LOCAL_EC2_REMOTE_DATASET_ROOT ?= datasets/local/$(LOCAL_DATASET_NAME)
LOCAL_EC2_REMOTE_DATA_YAML ?= config/generated/local_$(LOCAL_DATASET_NAME).yaml
LOCAL_EC2_TRAIN_NAME ?= local_$(LOCAL_DATASET_NAME)
LOCAL_EC2_REMOTE_FINAL_MODEL ?= models/ec2/local/$(LOCAL_DATASET_NAME)/$(EC2_TRAIN_PROFILE)/best.pt
LOCAL_EC2_ARTIFACT_ROOT ?= artifacts/local/$(LOCAL_DATASET_NAME)/$(EC2_TRAIN_PROFILE)
LOCAL_EC2_LATEST_RUN_FILE ?= $(LOCAL_EC2_ARTIFACT_ROOT)/latest-run.txt
LOCAL_EC2_LOCAL_ARTIFACT_ROOT ?= outputs/ec2/local/$(LOCAL_DATASET_NAME)/$(EC2_TRAIN_PROFILE)
LOCAL_FINAL_MODEL ?= models/local/$(LOCAL_DATASET_NAME)/$(EC2_TRAIN_PROFILE)/best.pt
```

新增 Make 目标：

```makefile
local-dir-ec2-upload-data
local-dir-ec2-train
local-dir-ec2-train-smoke
local-dir-ec2-train-baseline
local-dir-ec2-train-improve
local-dir-ec2-evaluate
local-dir-ec2-download-artifacts
local-dir-ec2-download-model
```

这些目标会复用 `scripts/cloud/ec2_diaper_workflow.py`，但需要先扩展该脚本支持：

```text
--remote-dataset-root
```

从而不再把远端数据目录硬编码成 `datasets/diaper_category/<country>/<version>`。

默认远端结构改为：

```text
/home/<EC2_USER>/yoloExample/datasets/local/<LOCAL_DATASET_NAME>/
/home/<EC2_USER>/yoloExample/config/generated/local_<LOCAL_DATASET_NAME>.yaml
/home/<EC2_USER>/yoloExample/models/ec2/local/<LOCAL_DATASET_NAME>/<profile>/best.pt
/home/<EC2_USER>/yoloExample/artifacts/local/<LOCAL_DATASET_NAME>/<profile>/
```

## 2026-09-14 导出目录可配置修正计划

### 问题

用户反馈本地目录导入/导出命令会创建类似：

```text
/Users/guobiao/PRO/me/yoloExample/datasets/local/Users/guobiao/DOC/森大2.0/18.陈列数据/GH/Softcare
```

这说明当前流程把 `LOCAL_DATASET_NAME` 同时当作“数据集短名称”和“输出目录片段”使用；如果用户在 Web 页面或命令行把本地图片目录/业务目录误填到 `LOCAL_DATASET_NAME`，Make 默认会拼出错误的嵌套目录。用户希望导出的目录可以明确指定。

### 修正方案

1. **新增显式导出根目录参数**：
   - 使用已有 `LOCAL_DATASET_ROOT` 作为正式导出目录参数，并在 Web 控制台中开放填写。
   - 页面文案改为“导出数据集目录”，避免用户把源图片目录填到数据集名称中。
   - 默认仍为 `$(PROJECT_ROOT)/datasets/local/$(LOCAL_DATASET_NAME)`。

2. **增加数据集名称校验**：
   - 新增 Make 校验目标，要求 `LOCAL_DATASET_NAME` 只能是短名称，不能包含 `/` 或以绝对路径形式传入。
   - 如果用户要自定义导出位置，必须填写 `LOCAL_DATASET_ROOT=/目标目录`，而不是把路径写到 `LOCAL_DATASET_NAME`。

3. **Web 控制台同步**：
   - 本地目录导入/标注相关命令增加 `LOCAL_DATASET_ROOT` 参数输入。
   - 增加参数定义和帮助说明。

4. **文档同步**：
   - 更新 `README.md`：说明 `LOCAL_IMAGES_DIR` 是源图片目录，`LOCAL_DATASET_ROOT` 是导出目录，`LOCAL_DATASET_NAME` 只填短名称。
   - 更新 `设计.md`：说明本地目录导出目录可配置。

5. **验证**：
   - `make -n ... LOCAL_DATASET_ROOT=/tmp/yolo-out` 应显示输出到指定目录。
   - `make -n ... LOCAL_DATASET_NAME=/Users/...` 应失败并提示使用 `LOCAL_DATASET_ROOT`。
   - 检查 Web `/api/config` 包含 `LOCAL_DATASET_ROOT`。
   - 运行已有本地导入单元测试与 `node --check web-console/server.js`。
