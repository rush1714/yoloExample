# EC2 纸尿裤标签名统一计划

## 问题

本地 `makefiles/diaper-category-ec2/Makefile.mk` 定义：

```make
DIAPER_LABEL_NAME ?= diaper
```

但 EC2 训练前自动生成 YAML 时，在 `scripts/cloud/ec2_diaper_workflow.py` 中将类别名硬编码为：

```yaml
names:
  0: 纸尿裤
```

因此本次 smoke 训练产物中的可视化图片显示 `纸尿裤`，而不是期望的 `diaper`。

## 目标

让 `DIAPER_LABEL_NAME` 成为本地 YAML、Label Studio、EC2 训练自动生成 YAML、推理显示和评估记录的一致单一来源。

## 修改方案

1. `scripts/cloud/ec2_diaper_workflow.py`：
   - 新增 `--label-name` 参数，默认 `diaper`。
   - `prepare_remote_dataset_yaml` 改为使用 `args.label_name`，不再硬编码 `纸尿裤`。

2. `makefiles/diaper-category-ec2/Makefile.mk`：
   - 在 `01` 到 `09` 所调用的 EC2 工具命令中传递：

     ```make
     --label-name '$(DIAPER_LABEL_NAME)'
     ```

3. `makefiles/diaper-category-ec2/README.md`：
   - 明确 `DIAPER_LABEL_NAME` 同时控制 Label Studio 标签与 EC2 YAML/模型可视化显示名。
   - 默认值当前是 `diaper`。

4. 验证：
   - EC2 工具 dry-run 中的 Base64 YAML 解码后包含 `0: diaper`。
   - Python 编译检查与 `git diff --check` 通过。
   - 不连接 EC2。

## 影响说明

- 已训练完成的 smoke 模型内部类别名仍是 `纸尿裤`，不会被本次代码修改自动改变。
- 要让模型训练/验证图显示 `diaper`，需在 EC2 `git pull` 后重新训练该 profile，或启动新的 baseline 训练。
