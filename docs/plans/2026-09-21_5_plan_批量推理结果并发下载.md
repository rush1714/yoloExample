# 批量推理结果并发下载优化计划

## 背景

用户反馈 `label-s3-ec2-download-predict-results` 当前按文件串行下载，虽然已经增加进度日志和 HTTP timeout，但结果文件和原始推理图片数量较多时仍然太慢。需要把结果文件下载和原图下载都改成可配置并发下载，同时保持清晰进度日志。

## 当前实现问题

- `scripts/s3/download_predict_results.py` 当前逐个下载 S3 结果文件。
- `download_source_images()` 当前逐个下载原始图片。
- 已有日志是串行日志，下载慢时仍会耗时很长。
- Make/Web 控制台已有 `EC2_PREDICT_SOURCE_DOWNLOAD_TIMEOUT`，但没有下载并发参数。

## 实现方案

### 1. 下载脚本增加并发能力

修改 `scripts/s3/download_predict_results.py`：

1. 引入 `ThreadPoolExecutor` / `as_completed`。
2. 新增 CLI 参数：
   - `--workers`，默认 `8`。
3. 结果文件下载：
   - 先读取 `uploaded_s3_uris.txt`。
   - 构造 `(index, total, uri, target)` 任务。
   - 并发下载 S3 结果文件。
   - 日志包含：
     - `result files to download: N, workers=M`
     - `start result file i/N ...`
     - `done result file i/N ...`
     - `failed result file i/N ...`
4. 原始图片下载：
   - 读取 `source_image_uris.txt`。
   - 构造 `(index, total, source, target)` 任务。
   - 并发下载 S3/HTTP/本地来源图片。
   - HTTP 下载继续使用 `--source-download-timeout`。
   - 日志包含：
     - `source images to download: N, workers=M, timeout=30s`
     - `start source image i/N ...`
     - `done source image i/N ...`
     - `failed source image i/N ...`
5. 失败不终止整批任务，继续写入下载报告。
6. `workers` 做下限保护，至少为 `1`。

### 2. Make 参数透传

修改 `makefiles/ec2/Makefile.mk`：

- 新增：
  ```make
  EC2_PREDICT_DOWNLOAD_WORKERS ?= 8
  ```
- `ec2-print-params` 打印该参数。

修改 `makefiles/label-workflow/Makefile.mk`：

- `label-s3-ec2-download-predict-results` 追加：
  ```bash
  --workers $(EC2_PREDICT_DOWNLOAD_WORKERS)
  ```

修改 `makefiles/brand-s3-ec2/Makefile.mk`：

- `brand-s3-ec2-download-predict-results` 同样追加 `--workers`。

### 3. 控制台参数补充

修改 `web-console/server.js`：

1. `PARAM_DEFINITIONS` 新增：
   - `EC2_PREDICT_DOWNLOAD_WORKERS`
   - 默认值 `8`
   - 类型 `number`
2. “下载 EC2 批量推理结果”命令参数列表加入该参数。
