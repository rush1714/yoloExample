# 陈列照片 YOLO 模型版本选型

## 沟通背景

用户询问：陈列照片识别使用 YOLO 哪个版本的模型比较好。

## 结论

当前项目建议继续以 Ultralytics YOLO26 检测模型作为主线：

- 本地 PoC / 第一版业务验证：`yolo26s.pt`。
- 生产服务器侧主力训练：`yolo26m.pt`。
- 手机端本地实时检测：`yolo26n.pt` 或 `yolo26s.pt`。
- `yolo26l.pt` / `yolo26x.pt`：只做效果上限实验，不作为首版默认。

## 推荐原因

陈列照片通常存在以下难点：

- 商品小、数量多。
- 包装互相遮挡。
- 货架层级复杂。
- 品牌 Logo 可能反光、模糊、倾斜。
- 同一张图里有多个品牌、多种包装。

因此不能只追求最快模型，也不能一开始使用过大的模型。推荐先用 `s` 尺寸建立稳定 baseline，再用 `m` 尺寸追求更高召回率。

## 具体选择

### 1. 本地 PoC：yolo26s.pt

适合在 MacBook 本地训练和验证，速度、显存、精度比较均衡。当前 `设计.md` 已将它作为 baseline。

推荐参数：

```bash
uv run python scripts/training/train.py \
  --base-model models/yolo26s.pt \
  --epochs 100 \
  --imgsz 960 \
  --batch -1 \
  --device mps
```

### 2. 生产服务器：yolo26m.pt

适合 EC2 GPU 或其他 NVIDIA GPU 服务器训练。对于陈列照片的小目标、密集目标，`m` 通常比 `s` 更值得作为生产主力候选。

推荐对比：

```text
yolo26s.pt: baseline，速度更快。
yolo26m.pt: 主力候选，召回率更值得期待。
yolo26l.pt: 效果上限实验，成本更高。
```

### 3. 手机端本地检测：yolo26n.pt / yolo26s.pt

如果业务要求手机离线或实时检测，先测试：

```text
yolo26n.pt + imgsz=640
yolo26s.pt + imgsz=640
```

如果小包装漏检明显，再尝试 `imgsz=960`，但必须真机验证延迟、耗电和温升。

## 不建议首版使用的方案

- 不建议直接上 `yolo26x.pt`：训练和推理成本高，迭代慢。
- 不建议把 YOLO-World / YOLOE 作为最终生产检测模型：它们更适合作为预标注和冷启动辅助，正式线上计数仍建议训练专用 YOLO 检测模型。
- 不建议只用 `yolo26n.pt` 做服务器侧正式识别：陈列照片小目标多，容易牺牲召回率。
