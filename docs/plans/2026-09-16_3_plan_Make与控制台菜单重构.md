# Make 与 YOLO 本地控制台菜单重构计划

## 背景

用户要求重新整理 `makefiles/*/Makefile.mk` 中的命令归属，当前 `makefiles/common/Makefile.mk` 中包含本地目录与 EC2 相关命令，不符合“common 只放公共能力”的边界。同时，YOLO 本地控制台需要按训练位置、图片来源、是否经过 OCR/预标注/视觉模型、上传/下载/LS 等维度重新归类，并支持菜单再次点击折叠/展开。

## 发现的问题

1. `common/Makefile.mk` 不仅有公共变量、Label Studio、本地训练/推理，还包含：
   - 本地目录导入/标注参数与目标；
   - `local-dir-ec2-*` 上传、训练、评估、下载目标。
   这会让 common 变成业务流程集合，后续维护不清晰。
2. EC2 训练仍有 `smoke` / `baseline` / `improve` 三类预设：
   - Make 目标如 `*-train-smoke`、`*-train-baseline`、`*-train-improve`；
   - Python 脚本中的 `TRAIN_PROFILES` 和 `--profile choices=[...]`；
   - Web 控制台菜单和参数仍暴露这些分类。
3. Web 控制台菜单目前是“一层分组 + 命令列表”，只能展开当前分组，不能点击同一菜单项折叠，也不支持二级/三级归类，导致 S3、EC2、本地 Mac、OCR、预标注、上传下载混在一起。
4. `设计.md`、`README.md`、各 `makefiles/*/README.md` 中仍记录旧命令和旧分类，需要同步更新。

## 重构目标

1. Makefile 模块边界统一：
   - `common` 只保留项目公共变量、Label Studio 基础能力、本地通用训练/推理、清理/备份/帮助等通用目标。
   - 本地图片目录导入/标注/本地目录 EC2 衔接迁移到独立目录。
   - EC2 公共连接与训练参数独立集中，纸尿裤、S3、本地目录流程复用同一套 EC2 参数。
2. 删除 `smoke` / `baseline` / `improve` 作为命令和代码中的训练分类。
   - 训练规模统一通过 `EC2_BASE_MODEL`、`EC2_TRAIN_EPOCHS`、`EC2_TRAIN_IMGSZ`、`EC2_TRAIN_BATCH`、`EC2_TRAIN_DEVICE` 等模型/训练参数表达。
   - 如需要区分输出目录，使用通用运行标识变量，例如 `EC2_RUN_NAME`，而不是预设档位。
3. Web 控制台按用户认知重新归类：
   - 训练位置：本地 Mac / EC2。
   - 图片来源：Excel / 本地目录 / S3。
   - 前置处理：无 / OCR / Ollama OCR / YOLO-World 预标注 / YOLOE visual prompt / 视觉参考图。
   - 阶段动作：上传、下载、Label Studio、转换 YOLO、训练、推理、数据浏览、维护。
   - 左侧菜单支持二级或三级折叠；再次点击已展开菜单可收起。
4. 修改后执行测试，确保 Make 目标、Python 脚本、Web 控制台配置接口可用。

## 计划修改方案

### 1. Makefile 目录与 include 重组

拟新增：

```text
makefiles/ec2/
├── Makefile.mk
└── README.md

makefiles/local-dir/
├── Makefile.mk
└── README.md
```

拟调整根 `Makefile` include 顺序：

```makefile
include makefiles/common/Makefile.mk
include makefiles/ec2/Makefile.mk
include makefiles/local-dir/Makefile.mk
include makefiles/brand-ocr-yoloworld/Makefile.mk
include makefiles/brand-llm-ocr-yoloworld/Makefile.mk
include makefiles/brand-local-visual-llm/Makefile.mk
include makefiles/brand-yoloe-visual/Makefile.mk
include makefiles/diaper-category-ec2/Makefile.mk
include makefiles/brand-s3-ec2/Makefile.mk
```

具体迁移：

- 从 `common/Makefile.mk` 移出本地目录相关变量与目标：
  - `LOCAL_*` 变量；
  - `local-dir-check`、`local-dir-yaml`、`local-dir-ls-import-json`、`local-dir-ls-apply`、`1-local-dir-workflow-to-ls`、`local-dir-ls-export`、`local-dir-ls-to-yolo`、`2-local-dir-workflow-after-ls`；
  - `local-dir-ec2-upload-data`、`local-dir-ec2-train`、`local-dir-ec2-evaluate`、`local-dir-ec2-download-artifacts`、`local-dir-ec2-download-model`。
- 将通用 EC2 连接和训练参数抽到 `makefiles/ec2/Makefile.mk`：
  - `EC2_HOST`、`EC2_USER`、`EC2_KEY`、`EC2_PORT`、`EC2_PROJECT_ROOT`、`EC2_ACTIVATE_CMD`、`EC2_PYTHON_CMD`、`EC2_TRAIN_DEVICE`、`EC2_TRAIN_BATCH`、`EC2_TRAIN_EPOCHS`、`EC2_TRAIN_IMGSZ`、`EC2_BASE_MODEL`、`EC2_EXECUTE`、`EC2_EVAL_NOTES`、`EC2_*_ARG` 等。
- `diaper-category-ec2`、`brand-s3-ec2`、`local-dir` 只保留各自数据集路径、YAML、manifest、目标命令和描述。

### 2. 删除 smoke / baseline / improve 分类

Make 目标调整方向：

- 删除或不再暴露：
  - `local-dir-ec2-train-smoke` / `local-dir-ec2-train-baseline` / `local-dir-ec2-train-improve`
  - `brand-s3-ec2-train-smoke` / `brand-s3-ec2-train-baseline` / `brand-s3-ec2-train-improve`
  - `03-1-diaper-ec2-train-smoke`、`04-1-diaper-ec2-train-baseline`、`05-1-diaper-ec2-train-improve` 等预设档位编号目标
- 保留统一目标：
  - `local-dir-ec2-train`
  - `brand-s3-ec2-train`
  - `diaper-ec2-train`
  - `*-ec2-evaluate`
  - `*-ec2-download-artifacts`
  - `*-ec2-download-model`
  - `diaper-ec2-predict`
- 输出目录中的 `<profile>` 改为通用 `$(EC2_RUN_NAME)`，默认如 `default`，需要区分实验时由用户传：

```bash
make diaper-ec2-train \
  EC2_BASE_MODEL=yolo26m.pt \
  EC2_TRAIN_EPOCHS=100 \
  EC2_TRAIN_IMGSZ=960 \
  EC2_RUN_NAME=yolo26m_960_e100
```

Python 脚本调整方向：

- `scripts/cloud/ec2_diaper_workflow.py` 与 `scripts/cloud/ec2_s3_workflow.py`：
  - 删除 `TRAIN_PROFILES` 和 `apply_profile_defaults()`；
  - 删除 `--profile choices=[smoke, baseline, improve, custom]` 语义；
  - 改为 `--run-name` 或等价参数，仅用于归档/报告标识；
  - `--base-model`、`--epochs`、`--imgsz` 改成明确默认值，不再从 profile 推导。
- 如 `scripts/reports/summarize_yolo_run.py` 仅用于报告字段，会同步替换参数名或兼容传入新的运行标识，避免报告中继续出现训练档位概念。

### 3. Web 控制台菜单重构

后端 `web-console/server.js`：

- 将 `COMMAND_GROUPS` 从扁平 `commands` 改造为支持嵌套 `children` 的结构，例如：

```text
数据总览
图片浏览
图片来源 / 标注准备
  ├─ Excel → OCR → YOLO-World → LS
  ├─ Excel → OCR → YOLOE Visual → LS
  ├─ Excel → Ollama OCR → YOLO-World → LS
  ├─ 本地目录 → LS
  └─ 本地目录 → S3 → LS
Label Studio
  ├─ 启停
  ├─ 导入
  └─ 导出 / 转 YOLO
本地 Mac 训练 / 推理
  ├─ 品牌 / 多品牌
  ├─ 本地目录数据集
  └─ 纸尿裤大类
EC2 训练 / 推理 / 下载
  ├─ 本地目录数据上传 EC2
  ├─ S3 manifest / 图片下载 / 训练
  └─ 纸尿裤数据上传 / 训练 / 推理 / 下载
维护工具
```

- 递归展开命令白名单，保证所有嵌套命令仍通过白名单执行。
- 移除 Web 白名单中所有 `smoke/baseline/improve` 目标和 `EC2_TRAIN_PROFILE` 参数。
- 增加/调整 `EC2_RUN_NAME` 参数定义，保留 `EC2_BASE_MODEL`、`EC2_TRAIN_EPOCHS`、`EC2_TRAIN_IMGSZ` 等显式训练参数。

前端 `web-console/public/index.html`：

- 左侧菜单支持多级树渲染。
- 点击分组：
  - 若分组未展开，则展开；
  - 若分组已展开，再次点击则折叠；
  - 点击具体命令才切换右侧命令详情。
- 当前选中命令高亮，父级保持展开状态。
- EC2 警告根据命令或分组元数据显示，而不是写死旧分组 ID。

## Web 控制台参数缓存计划（2026-09-16）

### 需求

用户要求 Web 控制台里输入过的参数缓存到浏览器中，并且同名参数在不同命令页面共享，避免切换菜单后重复输入，例如 `EC2_HOST`、`EC2_KEY`、`S3_DATASET_NAME`、`LOCAL_DATASET_NAME`、`BRAND` 等。

### 实施方案

1. 在 `web-console/public/index.html` 中使用 `localStorage` 保存参数缓存，key 使用 `yoloConsole:paramValues:v1`。
2. 以 Make 参数名作为缓存维度，同名参数跨命令共享同一份缓存值。
3. `paramInput(paramName)` 初始化输入框时，优先读取缓存值；没有缓存时才使用后端 `PARAM_DEFINITIONS` 的默认值。
4. 输入框或下拉框变化时实时保存缓存；清空输入框时删除该参数缓存，使 Makefile 默认值继续生效。
5. 在命令详情区增加“清空参数缓存”按钮，清空后当前表单回到默认值并刷新命令预览。
6. 同步更新 `设计.md` 和 `README.md` 的 Web 控制台说明。
