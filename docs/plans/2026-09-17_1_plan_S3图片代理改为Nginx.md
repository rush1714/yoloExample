# S3 图片代理改为本地 Nginx 计划

## 背景

当前 `scripts/s3/s3_image_proxy.py` 使用 Python `ThreadingHTTPServer` + boto3：每次 Label Studio 请求图片时都由 Python 拉取 S3 对象并一次性读入内存后返回。图片数量较多或单张较大时，浏览器加载会明显变慢。

用户希望改为“本地启动一个 nginx 就可以”，用 Nginx 承担图片转发、缓存和 CORS 响应。

## 已阅读上下文

- `设计.md`：S3 → Label Studio → EC2 流程当前约定默认使用本地 S3 图片代理规避 CORS。
- `scripts/s3/s3_image_proxy.py`：当前 Python 代理实现。
- `scripts/s3/brand_s3_config.py`：S3 URL、proxy URL、配置加载公共逻辑。
- `scripts/label_studio/generate_s3_import.py`：根据 manifest 生成 Label Studio 导入 JSON。
- `scripts/s3/upload_images_to_s3.py`：上传后 manifest 当前包含 `s3_uri`、`https_url`、`proxy_url`。
- `makefiles/brand-s3-ec2/Makefile.mk` 与 `makefiles/brand-s3-ec2/README.md`：现有 Make 入口和文档。
- `web-console/server.js`：Web 控制台中现有 “启动 S3 图片代理” 命令入口。

## 关键判断

- 如果 S3 对象是公开可读的，Nginx 可以直接反向代理 S3 HTTPS 地址，并补充 CORS header。
- 如果 S3 对象仍是私有桶，纯 Nginx 不能自己完成 AWS SigV4 签名；推荐做法是：先由本地脚本基于现有 AWS profile 生成短期预签名 URL 映射文件，Nginx 再按映射转发和缓存图片。这样请求热路径不再经过 Python，且仍支持私有桶。
- 因此实现上不删除 Python 代理，保留为兜底；新增 Nginx 代理作为默认/推荐路径。

## 拟实施方案

1. 新增 Nginx 图片代理渲染脚本
   - 新增 `scripts/s3/render_nginx_image_proxy.py`。
   - 从 `config/brand_s3_ec2.local.yaml` / Make 变量 / manifest 读取桶、region、endpoint、proxy base、allowed origin 等参数。
   - 根据 manifest 为每张图片生成稳定本地 URL，例如：
     - `http://127.0.0.1:3010/image/<dataset>/<hash><ext>`
   - 生成 Nginx 配置与 URI → 上游图片地址 map：
     - `direct` 模式：上游为普通 S3 HTTPS URL，适用于公开对象。
     - `presign` 模式：上游为 boto3 生成的 S3 预签名 URL，适用于私有桶，默认有效期 7 天。
   - Nginx 配置启用：
     - `proxy_cache` 本地缓存；
     - `proxy_cache_lock` 防止同一图片并发回源；
     - CORS 响应头；
     - `X-Cache-Status` 便于观察缓存命中。

2. 扩展公共 URL 生成逻辑
   - 在 `scripts/s3/brand_s3_config.py` 增加 Nginx 本地图片 URL helper。
   - `generate_s3_import.py` 增加 `image_url_mode=nginx`，让 Label Studio 导入 JSON 使用 Nginx 本地 URL。
   - 保持现有 `proxy`、`https`、`s3` 模式兼容。

3. 调整 Make 入口
   - 新增变量：
     - `S3_PROXY_BACKEND ?= nginx`
     - `S3_NGINX_MODE ?= presign`
     - `S3_NGINX_BIN ?= nginx`
     - `S3_NGINX_PRESIGN_EXPIRES ?= 604800`
     - `S3_NGINX_CACHE_DIR`、`S3_NGINX_CONF`、`S3_NGINX_PID` 等本地运行文件路径。
   - 新增目标：
     - `brand-s3-nginx-render-config`：生成 Nginx 配置和 map。
     - `brand-s3-nginx-start`：本地启动 Nginx。
     - `brand-s3-nginx-stop`：停止本地 Nginx。
     - `brand-s3-nginx-reload`：重新生成配置并 reload。
     - `brand-s3-python-proxy-start`：保留旧 Python 代理入口。
   - 将 `brand-s3-proxy-start` 改为按 `S3_PROXY_BACKEND` 调度，默认走 Nginx；如需旧实现可传 `S3_PROXY_BACKEND=python`。

4. 更新 Web 控制台与文档
   - `web-console/server.js` 的 S3 参数区补充 Nginx 相关变量。
   - 更新 `config/brand_s3_ec2.example.yaml`、`scripts/README.md`、`makefiles/brand-s3-ec2/README.md`。
   - 更新 `设计.md` 中 S3 训练图片管理章节，把默认代理从 Python 改为 Nginx，并说明私有桶使用预签名 map、过期后需重新生成/重启或 reload。

5. 测试与静态检查
   - 扩展 `tests/test_brand_s3_ec2_workflow.py`，覆盖：
     - Nginx 本地 URL 生成稳定且不暴露原始长 key；
     - `image_url_mode=nginx` 时 Label Studio 导入任务使用 Nginx URL；
     - 渲染出的 Nginx 配置包含 cache、CORS、map 和对象上游地址。
   - 执行：
     - `uv run python -m unittest tests.test_brand_s3_ec2_workflow`
     - `uv run pylint scripts/s3/brand_s3_config.py scripts/s3/render_nginx_image_proxy.py scripts/label_studio/generate_s3_import.py tests/test_brand_s3_ec2_workflow.py`

## 使用方式预期

私有桶推荐流程：

```bash
make brand-s3-upload-images \
  S3_DATASET_NAME=<name> \
  S3_LOCAL_IMAGES_DIR=/path/to/images \
  S3_BUCKET=<bucket> \
  S3_PREFIX=<prefix> \
  S3_REGION=<region> \
  S3_PROFILE=<profile>

make brand-s3-nginx-start \
  S3_DATASET_NAME=<name> \
  S3_BUCKET=<bucket> \
  S3_REGION=<region> \
  S3_PROFILE=<profile> \
  S3_NGINX_MODE=presign

make brand-s3-ls-import-json \
  S3_DATASET_NAME=<name> \
  S3_IMAGE_URL_MODE=nginx
```

公开对象可用：

```bash
make brand-s3-nginx-start S3_DATASET_NAME=<name> S3_NGINX_MODE=direct
make brand-s3-ls-import-json S3_DATASET_NAME=<name> S3_IMAGE_URL_MODE=nginx
```

## 风险与注意事项

- `presign` 模式会生成有有效期的 URL；默认 7 天，到期前需要重新执行 `brand-s3-nginx-reload` 刷新 Nginx map。由于 Label Studio 里保存的是稳定短 URL，S3 key 不变时通常不需要重新导入 LS JSON。
- 本地必须安装 `nginx` 命令；若未安装，需要用户自行安装（macOS 可用 Homebrew，Linux 可用系统包管理器）。
- Nginx 只监听 `127.0.0.1`，避免把本地图片代理暴露给局域网。
- Python 代理暂时保留，方便在 Nginx 不可用时回退。
